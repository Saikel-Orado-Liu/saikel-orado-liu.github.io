# 响应式布局设计规范

> 配套总纲：`docs/网页设计规范.md`（V4.0）
> 目标：一套可维护的、覆盖桌面/平板/手机/超宽屏/软键盘 / RTL 的响应式体系，任何新增页面零心智负担地遵循。

---

## 1. 断点体系（唯一清单）

全站只允许以下断点值。**新增断点必须先改本文件**，不得在组件中凭空引入。

| 别名 | CSS 值 | 别名（Nav 版） | 典型设备 | 用途 |
| --- | --- | --- | --- | --- |
| `--bp-mobile` | `max-width: 640px` | Mobile | iPhone 15 Pro Max (430)、Pixel 8 (412) | 手机竖屏；导航折叠、单列栅格 |
| `--bp-footer` | `min-width: 768px` | — | iPad Mini 竖屏 (768/744) | 页脚双栏、社交组横排 |
| `--bp-doc` | `max-width: 860px` | — | iPad Pro 11 竖屏 (834)、Surface Go (768) | 文档页隐藏左侧文档树 |
| `--bp-pad` | `641px – 1007px` | Pad | iPad Air 横屏 (1180→无效区间归桌面) | 平板/手机横屏；导航隐藏标题 |
| `--bp-desktop` | `min-width: 1008px` | Desktop | >=1008px | 桌面三栏导航 |
| `--bp-docwide` | `max-width: 1200px` | — | 笔记本 1280 减滚动条 | 文档页隐藏右侧 TOC |

> **为什么不使用 Tailwind 内置断点**：站点既有实现使用 `max-[1007px]` / `max-[640px]`（Tailwind 4 任意值语法），与上表一致；**禁止**混用 Tailwind 默认 `sm/md/lg/xl`（其语义与本站断点不同，会造成"伪响应式"）。

## 2. 核心布局行为

### 2.1 导航栏 `.navbar`

| 断点 | 行为 | 关键规则 |
| --- | --- | --- |
| Desktop ≥1008px | 水平三栏 | `padding: 0 var(--space-xl)`；标题 + 水平凹槽选项卡 + 右侧控件 |
| Pad 641–1007px | 水平两栏 | `.navbar-title { display: none }`；`padding: 0 var(--space-lg)` |
| Mobile ≤640px | **折叠两行** | `flex-direction: column`；第一行 = 品牌 + 控件（widget `order:1; align-self:flex-end; margin-top:-2.25rem` 上提与品牌同行）；第二行 = 纵向凹槽菜单（`ul` column，链接全宽，`padding: 0.6rem 1rem`） |

**移动端滑块规则（V4.0）**：凹槽滑块是桌面横向布局的几何产物（JS 按 `<li>` rect 计算 left/width）。移动端菜单为纵向列表时滑块几何失效（历史上表现为竖排红条），**必须**：

```css
@media (max-width: 640px) {
  .navbar .navbar-nav .nav-slider { display: none; }
}
```

选中态由 `a.active` 自身的强调色亚克力板承担（该样式已存在，无需新增）。**禁止**为移动端恢复/修改滑块 JS。

**溢出治理**：`body { overflow-x: clip }` 为全局兜底（`base.css`）。任何横向滚动问题应修根因（wrap / min-width / 字号 clamp），而不是仅靠剪裁掩盖。

### 2.2 网格（Grid）

| 场景 | 桌面 | Pad | Mobile |
| --- | --- | --- | --- |
| 特色模块（3 卡） | `grid-cols-3 gap-8` | `max-[1007px]:grid-cols-2` | `max-[640px]:grid-cols-1` |
| 卡片双列 | `grid-cols-2 gap-8` | `grid-cols-2` | `max-[640px]:grid-cols-1` |

- 列间距统一 `gap-8`（=`--space-xl` 32px）
- 卡片高度弹性：`.card-layout { flex-col; gap-0 }` + `.card-body { flex: 1 }` 保证同排等高
- 移动端单列时卡片不压缩正文，保留 `--space-xl` 内边距

### 2.3 内容容器

| 容器 | 桌面 | ≤640px |
| --- | --- | --- |
| `.container` | `max-width: 1152px; padding: 0 24px` | `padding: 0 3vw` |
| `.container-narrow` | `max-width: 720px; padding: 0 24px` | `padding: 0 3vw` |
| `.navbar` / `.footer` | `max-width: 1280px; width: calc(100% - 48px)` | 同左（宽度百分比自适应） |

> `3vw` 规则：移动端容器左右留白在 12–24px 之间线性缩放（640×3%≈19px）。

### 2.4 Hero

| 属性 | 桌面 | ≤640px |
| --- | --- | --- |
| 高度 | `min-height: 48vh` | 同（48vh ≈ 手机一屏内） |
| 标题 | `.heading-xl`（48px） | `clamp(24px, 7.5vw, 40px)` |
| 副标题 | `text-xl max-w-[480px]` | 同（自动换行） |
| 头像 | 128px 圆形 | 96–128px（Tailwind 类保持 128，已可容纳） |
| 按钮组 | `flex gap-4` | 允许 `flex-wrap`（按钮 2 行） |

**约束**：hero 内标题与副标题不得 `white-space: nowrap`；不得给 `.hero-content` 设定 `min-width`；标题行若超过可用宽度必须换行（CJK 断行 + `overflow-wrap: break-word` 用于长拉丁词）。

### 2.5 文档页 `.doc-layout`

| 断点 | 布局 | 规则 |
| --- | --- | --- |
| ≥1200px | 三栏 | `grid-template-columns: minmax(0, 250px) 1fr minmax(0, 250px); gap: var(--space-lg); max-width: 1280px` |
| 860–1199px | 两栏 | `minmax(0, 250px) 1fr`；`.doc-sidebar-right { display: none }` |
| <860px | 单栏 | `1fr`；`.doc-sidebar-left { display: none }` |

- 侧边栏 `position: sticky; top: var(--space-lg); align-self: start`，容器 `max-height: calc(100vh - var(--header-height) - var(--space-2xl))` + 内部滚动
- 主内容列 `min-width: 0`（防止长代码块/表格撑破网格）
- 中间列实际渲染宽度：1280 − 250×2 − 24×2 = 732px ≈ `--content-narrow`（720px）语义

### 2.6 页脚 `.footer`

| 断点 | 布局 |
| --- | --- |
| ≥768px | `flex-direction: row; justify-content: space-between`；右栏 `align-items: flex-end` |
| <768px | `flex-direction: column`；社交图标组**允许换行**（`.footer-socials { flex-wrap: wrap; row-gap: var(--space-md) }`），组内间距降至 `--space-md` |

**V4.0 修复**：此前 `.footer-socials` 单行不换行，在 390px 真机视口产生 493px 的横向滚动（两组图标 + 分隔线 = 406px > 342px 可用宽度）。这是全程唯一被真机验证的横向溢出源。

### 2.7 前后篇导航 `.doc-pager`

| 断点 | 布局 |
| --- | --- |
| ≥641px | `grid-template-columns: 1fr 1fr; gap: var(--space-lg)` |
| ≤640px | 单列 `1fr; gap: var(--space-md)`；卡内 `padding: var(--space-md) var(--space-lg)` |

## 3. 排版自适应规则

| 场景 | 规则 |
| --- | --- |
| 标题 4xl+ | ≤640px 使用 `clamp()` 或降一档（见总纲 §3.3） |
| 正文 | 基准 16px；桌面正文列宽 720px 上限保证 45–75 字符/行 |
| 长拉丁串/URL | `overflow-wrap: break-word`（`.article-content table` 已有）；链接图标不换行 |
| 触控 | 链接/按钮最小触控高度 24px（WCAG 2.2 SC 2.5.8），建议 44px；导航移动端链接 `padding: 0.6rem 1rem` 满足 44px |
| 视口 | `<meta name="viewport" content="width=device-width, initial-scale=1.0" />`（BaseLayout 已含，禁止删除） |

## 4. 溢出治理清单（新组件必查）

1. 任何 `flex` 行容器：检查其 min-content 宽度是否可能超过容器 → 加 `flex-wrap: wrap` 或 `min-width: 0`
2. 任何 `position: absolute` 定位的伪元素/装饰：`inset: auto ...` 需保持在父级 0～100% 范围内
3. 标题/徽标类长文本：`white-space: nowrap` 只允许用于装饰性短串（如 ribbon）
4. 全局兜底 `body { overflow-x: clip }` 存在，但**只能作为兜底**，验收标准是 `document.documentElement.scrollWidth <= clientWidth`
5. 截图验证矩阵（见 §7）完成后才可交付

## 5. RTL 适配（ar-sa）

| 维度 | 规则 |
| --- | --- |
| 方向 | `<html dir="rtl">` 由 `getLocaleDir()` 输出，逻辑方向（start/end）由浏览器自动镜像 |
| 布局 | 仅使用逻辑属性：`padding-inline` / `margin-inline` / `inset-inline` / `text-align: start`；CSS 中 `left/right` 仅用于纯装饰（阴影、光效），**不得**用于排版定位 |
| 阴影 | 三层阴影（L1 右下切边 / L2 右下柔影）。RTL 下保持**物理光从左上入射**不变（阴影不镜像），符合"同一块板"的直觉；不做 `dir` 选择器翻转 |
| 滑块 | 凹槽滑块 `left`/`width` 定位为物理像素；RTL 下视觉排版镜像，验证 `ar-sa` 页面滑块不越界（若越界则回退为隐藏滑块 + active 静态样式，同移动端策略） |
| 字体 | MiSans 无阿拉伯字形 → 回退 `system-ui`；验证行高、基线对齐 |
| 验收 | ar-sa 首页、任意项目文档页：无横向滚动、导航/页脚无遮挡 |

## 6. 验证矩阵（开发-交付流程）

每个响应式改动必须过以下「截图矩阵」（配合总纲流程规范，见 `docs/组件设计规范.md` §11）：

| # | 视口 | 主题 | 页面 | 检查点 |
| --- | --- | --- | --- | --- |
| 1 | 1440（桌面） | 暗 | `/`、`/projects/texturge/`、`/blog/` | 三栏导航、网格、文档三栏 |
| 2 | 1440 | 亮 | 同上 | 明暗几何同构、噪点路径 |
| 3 | 768 | 暗 | `/` | 导航隐藏标题、栅格 2 列 |
| 4 | 430（手机） | 暗 | `/`、文档页 | 导航折叠、菜单选中态、无横向滚动 |
| 5 | 430 | 亮 | `/` | 同 4 |
| 6 | 390 | RTL `/ar-sa/` | `/` | 镜像布局、无溢出 |

> **截图工具链**（实测可用）：Microsoft Edge headless：
> ```
> msedge --headless=new --disable-gpu --no-first-run --disable-extensions --hide-scrollbars
>        --virtual-time-budget=6000 --screenshot=out.png --window-size=W,H URL
> ```
> - **暗色**：直接截图（系统/headless 默认 `prefers-color-scheme: dark`）
> - **亮色**：先在 `public/` 放临时引导页 `flash.html`：`localStorage.setItem('theme','light');location.replace('/')`，对引导页截图（同源 localStorage 生效），用完删除
> - **⚠️ 已知坑**：该 Edge 发行版 `--window-size` 小于约 500px 时视口被钳制（实测 390 请求得到 496 CSS px）。**真机级别视口验证**用同源 iframe 探针页（iframe style width=390 为真实 CSS px）；或用 DevTools 设备模拟（CDP）。文档编写时以探针测量的 `scrollWidth/clientWidth` 数值为准，不以截图裁切为准。

> **整页审查协议（全局 + 细节双参考）**：一张全页截图（1440×**≤5200px**）即可同时获得"全局布局参考"与"细节参考"——宿主侧 dsh-vision-enhancer 会保留原图（全局布局）并按 800×800 / 15% 重叠追加**全分辨率细节裁片**（每张带像素范围标注）。裁片计数公式：宽 1440 → 2 列；高 H → `ceil((H-800)/680)+1` 行（尾行贴边去重）；合计 = 2 × 行数。示例：H=1000 → 4 张；H=4600 → 14 张；H=5200 → 16 张。**截图高度超 5200px 时改用区块补拍**（每区块 ≈ 1440×1000 ≈ 4 张裁片）；日常小改动直接用区块截图（更省 token）。

## 8. 实测溢出修复记录（2026-09-11）

以同源 iframe 探针实测 5 个代表页面 × 5 档视口（390 / 430 / 768 / 1008 / 1440），发现并修复两处**实现与本节规范不一致**导致的横向滚动（规范值未变）：

| # | 症状 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 文档页 ≤768px 溢出 8px（`scrollWidth 776 > 768`）；≤860px 时左侧栏整屏铺满、正文被挤到折叠线以下 | `doc-shared.css` 中隐藏侧栏的 `@media` 块写在 `.doc-sidebar { display: flex }` **之前**：同为单类选择器、权重相同，后置的 `display: flex` 覆盖了 `display: none`，**侧栏实际从未隐藏**，与 §2.5 断点表（<860 单栏、两侧隐藏）不符 | 将 `@media (max-width: 1200px) { .doc-sidebar-right }` 与 `@media (max-width: 860px) { .doc-sidebar-left }` 移至 `.doc-sidebar` 基样式**之后** |
| 2 | `/en-us/` 在 768px 溢出 42px（英文文案更长时暴露） | `.footer-inner` 在 ≥768px 为**不可换行**的行容器，且 `.footer-left { flex-shrink: 0 }` 保持自然宽度：左栏 438px + 右栏 228px > 可用 624px，无让步空间 | 按 §4 第 1 条「flex 行容器加 `flex-wrap`」：`.footer-inner` 加 `flex-wrap: wrap` + `row-gap: var(--space-lg)`；`.footer-right` 加 `min-width: 0` 允许收缩（`.footer-socials` 本就允许换行） |

> 修复后 25 个组合（5 页 × 5 断点）全部满足 `scrollWidth == clientWidth`；1440px 桌面端与修复前**逐字节一致**（零回归）。
>
> **遗留风险提示**：`.doc-scroll-wrapper` 的 `margin: 0 calc(0px - var(--space-xl))` 出血量（32px）大于侧栏卡片 16px 内边距，是第 1 条溢出的放大器。侧栏隐藏后不再触发，但**今后任何内边距 < 32px 的容器再套用该 wrapper 时必须重新评估**。
