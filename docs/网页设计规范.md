# 网页设计规范（总纲）

> 适用版本：Astro v7.2 · TypeScript 5.8 · Tailwind CSS 4.3
> 设计语言：Material Design 3 + 抽象拟物（Abstract Skeuomorphism）混合
> 规范蓝本：`/spec/` 设计规范预览页

## 0. 规范文档体系（V4.0 起）

本文件为**总纲**，只定义设计基础（哲学、令牌、材质、通用规则）与组件矩阵，不再承载组件的完整细节。V4.0 将内容拆分到以下专题文档，职责边界：

| 文档 | 内容 | 状态 |
| --- | --- | --- |
| 本文件 | 设计哲学 / 色彩 / 字体 / 形状 / 阴影与厚度体系 / 材质管线 / 布局容器 / 画布设计 | 正式 |
| `组件设计规范.md` | 每个组件的规格表：结构、尺寸、状态机、明暗对照、实现文件、动效引用 | 正式 |
| `响应式设计规范.md` | 断点体系、导航折叠、文档三栏、栅格、溢出治理、RTL 适配、截图矩阵 | 正式 |
| `动效设计规范.md` | 动效令牌、缓动体系、组件动效矩阵、View Transition、RTL 语义、reduced-motion | 正式 |
| `无障碍设计规范.md` | WCAG 2.2 AA 目标、对比度表、焦点、键盘、触控、语义、检查清单 | 正式 |

> **单一事实源原则**：任何组件的"最终值"以**代码实现**为准；若本文档与代码冲突，先修代码再改文档（漂移治理，见 §12）。

### 0.1 样式规范参考页（审查基准）与分离约束

`/spec/`（设计令牌）与 `/spec/components/`（控件展示）构成**独立的样式规范参考书**，供设计师/用户审查与纠错。架构要求：

| 规则 | 说明 |
| --- | --- |
| **独立实现** | 参考页页面实体位于 `src/spec/`（**不在 `src/pages/` 下**），使用专属 `src/layouts/SpecLayout.astro` + `src/styles/specbook.css`，**不 import 主站任何样式/组件/基础布局**（无 BaseLayout、无 base/components/ui-spec/tokens/material、无既有组件） |
| **禁止反向依赖** | 主站**禁止 import** specbook.css 或 SpecLayout；两者代码零共享 |
| **只共享数值标准** | 参考页与主站仅共享"标准值"（10 色、板级三层阴影、令牌数值）；改动时必须同步两侧并更新本规范修订记录 |
| **变更流程** | 任何样式/行为变更：先在参考页独立实现 → 截图/审查通过（用户为审查人）→ 再同步主站实现 → 全站编译与截图验证 |
| **命名隔离** | 参考页类统一 `sb-` 前缀、主题属性为 `data-spec-theme`（独立于主站 `light-style`），杜绝 class 冲突与样式依赖 |
| **不出站（结构性）** | 参考页**只在 `astro dev` 注入路由**（`astro.config.mjs` 的 `specLocalOnly()` 集成）：`astro build` 永不产出 `/spec/`，产物中根本不存在该页面。`noindex, nofollow` 与 sitemap 排除仅作为纵深防御保留 |
| **产物守卫** | `scripts/verify-public-output.mjs` 在 `pnpm build` 中校验 `dist/` 不含 `spec/`、`gosper-test.html` 等内部路径，一旦泄漏直接构建失败 |

> **⚠️ 重要认知（V4.2 纠偏）**：GitHub Pages 上传的是**整个 `dist/`**，因此「写进 `src/pages/` 的页面 = 公网可访问」。
> `noindex` 只阻止**搜索引擎收录**，**不是访问控制** —— 任何人直接输入 URL 都能打开。
> 内部页面的唯一可靠做法是**让它不进产物**：页面放非路由目录 + 只在 dev 注入路由；静态调试页放 `tools/` 等非发布目录（禁止放 `public/`）。

**V4.1 参考页审查修订（实现向规范回归，规范值未变）**：

| # | 问题 | 处理 |

**V4.2 参考页可见性纠偏（内部页不得进产物）**：

| --- | --- | --- |

## 1. 设计哲学

### 1.1 抽象拟物风格

本项目采用 **Material Design 3（M3）** 与 **抽象拟物（Abstract Skeuomorphism）** 的混合设计语言。

**核心思想**：将软件中的虚拟实体对应到现实生活中的真实实体进行抽象化提取——或者说，是虚拟实体真正在现实中可能呈现的样式。

- UI 表面平整、整洁干净
- 组件不透明，但具有明确的体积感和观感上的"厚度"
- 整体效果类似于**不透明磨砂亚克力板材质**——每个组件都是一块写了字的"亚克力板"
- 通过高光、反射和阴影塑造立体感，不能完全扁平

**M3 骨架**：色彩系统遵循 M3 的 Color Role 体系，形状体系遵循 M3 Shape Scale，提供系统化的层级感知。

**Tailwind 工具层**：CSS 变量通过 `@theme` 注册到 Tailwind 4.3（`src/styles/global.css`），所有设计 Token 均可作为 Tailwind 工具类使用（如 `text-primary`、`rounded-md`、`shadow-far`）。组件中的 flex 布局、间距、字号等通用样式优先使用 Tailwind；拟物质感（噪点、color-mix、多层阴影、clip-path）保留手写 CSS。

**暗色优先**：默认主题为暗色（`:root` 即暗色 Token），亮色通过手动 `:root.light-style` 类覆盖（JS 内联脚本在首帧前执行，防 FOUC）+ `@media (prefers-color-scheme: light)` 双路径（tokens.css / base.css 保留 media 路径）。

### 1.2 设计原则

| 原则 | 说明 |
| --- | --- |
| **体积感优先** | 所有组件必须具备观感上的"厚度"——通过多层阴影、切边、内嵌暗边实现亚克力板的物理体积 |
| **强交互动画** | 拟物风格要求动画必须具备交互感：按钮按下沉入、hover 抬起、滑块在凹槽中物理滑动 |
| **不透明亚克力板** | 组件为实色基底 + SVG 噪点纹理 + 漫反射高光，不做毛玻璃半透明（暗色/亮色统一使用实色） |
| **明暗几何同构** | 同一组件在暗色/亮色下的阴影**几何参数**（偏移、模糊、厚度）完全一致，只切换色谱与噪点混合路径 |
| **多语言包容** | 10 种语言支持，阿拉伯语 RTL 方向适配，locale 感知路由 |
| **可访问优先** | WCAG 2.2 AA 为目标；焦点环、键盘路径、减动效偏好在设计阶段就位（详见无障碍规范） |

## 2. 色彩系统

### 2.1 10 色体系

项目所有颜色定义在 `src/styles/tokens.css`，由 **10 个用户自定义色**（`--clr-*`）通过 `var()` 和 `color-mix()` 派生全部 M3 Color Role。

**暗色模式（默认 `:root`）：**

| 层级 | 变量 | 暗色值 | 语义角色 |
| --- | --- | --- | --- |
| 根 | `--clr-base-bg` | `#141414` | 页面底层背景 |
| 根 | `--clr-aux-bg` | `#242424` | 次级表面 |
| 根 | `--clr-primary-accent` | `#FF1500` | 主强调色 |
| 根 | `--clr-primary-text` | `#F5F5F5` | 主文本色 |
| 一次 | `--clr-primary-bg` | `#262626` | 卡片/组件默认背景 |
| 一次 | `--clr-secondary-accent` | `#FF6B6B` | 次强调色 |
| 二次 | `--clr-secondary-bg` | `#333333` | 元素 hover 背景 |
| 二次 | `--clr-secondary-text` | `#ADADAD` | 副标题、说明文字 |
| 特殊 | `--clr-error` | `#00BFA5` | 错误状态 |
| 特殊 | `--clr-warning` | `#FFC800` | 提醒/警告 |

**亮色模式（`:root.light-style` / `@media light`）：**

| 变量 | 亮色值 | 说明 |
| --- | --- | --- |
| `--clr-base-bg` | `#FAFAFA` | 暖白底 |
| `--clr-aux-bg` | `#EDE4D6` | 暖灰次级表面 |
| `--clr-primary-accent` | `#E89800` | 橙金色强调 |
| `--clr-primary-text` | `color-mix(#1a1a1a, accent 15%)` — 暖褐调 | 减轻中性色在暖底上的冷感 |
| `--clr-primary-bg` | `#FFFFFF` | 纯白卡片基底 |
| `--clr-secondary-accent` | `#FFD54F` | 暖黄次强调（⚠️ 仅用于装饰/上屏图形，**禁止**用作正文色/焦点环——对比不足） |
| `--clr-secondary-bg` | `#E8E8E8` | — |
| `--clr-secondary-text` | `color-mix(accent 55%, text)` — 暖琥珀褐（4.8:1 ✓） | 匹配卡底色 |
| `--clr-error` | `#BA1A1A` | 红色错误 |
| `--clr-warning` | `#F28D00` | 橙色提醒 |

> **设计原则**：这 10 个颜色是项目唯一的色彩设计参考。所有组件、页面、状态的颜色必须来源于这 10 色。通过 `color-mix()` 派生的**次生色**（如 `--md-sys-color-primary-container`、`--md-sys-color-outline` 等）仅服务于 CSS 工程实现，不作为独立设计决策。

### 2.2 主题切换

由 `src/scripts/theme.ts` 驱动，三层优先级：

1. `localStorage.getItem('theme')` — 用户手动选择（最高优先）
2. `prefers-color-scheme` — 系统偏好
3. 默认暗色 — 无偏好时的回退

切换时使用 **View Transition API** 实现圆形辐射动画——从鼠标点击位置向外扩散展开新主题（详见动效规范 §6）。

**同步机制**：`BaseLayout.astro` 内联脚本在首帧前应用主题（防 FOUC）；`astro:after-swap` 在客户端导航前同步主题、`lang`、`dir`。

### 2.3 色彩适用场景速查

| 10 色 | 典型用途 |
| --- | --- |
| 底背景色 | `body` 背景 |
| 辅背景色 | 行内代码背景（凹槽轨道混合源） |
| 主背景色 | 卡片、按钮、页脚亚克力板基底 |
| 次背景色 | 元素 hover/active 态背景 |
| 主强调色 | 链接、btn-primary、选中色、亮色模式焦点环 |
| 次强调色 | 链接 hover、暗色模式焦点环、次要高亮 |
| 主文本色 | 标题、正文 |
| 次文本色 | 副标题、日期、说明文字 |
| 提醒色 | tag-accent、badge-coming-soon |
| 错误色 | 错误状态（暗色 #00BFA5 / 亮色 #BA1A1A） |

> 链接 hover 使用错误色对（暗色 → `--clr-error` 青绿，亮色 → `--clr-error` 深红）：主强调为暖红，hover 与之互补，形成"红→青"的赛博感反馈；该行为是**有意的设计决策**，勿改为次强调色。

## 3. 字体与排版

### 3.1 字体栈

| 字体 | CSS font-family 名称 | 来源 | 用途 |
| --- | --- | --- | --- |
| MiSans | `MiSans` | 小米官方 CDN（`cdn-font.hyperos.mi.com`） | 全语言正文 — Latin + Chinese Simplified，全部 10 字重 |
| JetBrains Mono | `JetBrains Mono` | Google Fonts CDN | 等宽代码字体 |
| System UI | `system-ui, -apple-system, sans-serif` | 系统内置 | 最终回退 |

**字体加载方式**（`src/layouts/BaseLayout.astro` `<head>`）：

```html
<link rel="preconnect" href="https://cdn-font.hyperos.mi.com" crossorigin />
<link rel="stylesheet" href="https://cdn-font.hyperos.mi.com/font/css?family=MiSans:100,200,300,400,450,500,600,650,700,900:Chinese_Simplify,Latin&display=swap" />
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=JetBrains+Mono:wght@300;400;500;600;700&display=swap" />
```

> **为什么用 `<link>` 而非 CSS `@import`**：Vite 打包后的 CSS 中 `@import` 不被浏览器正确处理——外部 URL 的 `@import` 被忽略。所有外部字体必须用 `<link rel=stylesheet>` 在 HTML `<head>` 中加载。

**字体栈变量**（`src/styles/tokens.css`）：

```css
--font-sans: 'MiSans', system-ui, -apple-system, sans-serif;
--font-mono: 'JetBrains Mono', 'Fira Code', 'Cascadia Code', Consolas, monospace;
```

#### 3.1.1 字重对齐（MiSans CDN 提供的值：100/200/300/400/450/500/600/650/700/900）

| 设计语义 | CSS Token | 值 | CDN 匹配 |
| --- | --- | --- | --- |
| Light | `--font-weight-light` | 300 | 300 ✓ |
| Regular | `--font-weight-regular` | **400** | 400 ✓ |
| Medium | `--font-weight-medium` | **500** | 500 ✓ |
| Semibold | `--font-weight-semibold` | **600** | 600 ✓ |
| Bold | `--font-weight-bold` | **700** | 700 ✓ |

> **semibold 修正（V4.0）**：`--font-weight-semibold: 600` 为 V4.0 新增。此前 `components.css` h3 与 `doc-shared.css` doc-pager-title 引用了未定义变量，导致实际渲染为 400（继承值）。**任何新的字重引用必须先确认 token 存在**；未定义 token 会使属性失效并静默回退。

> **`<strong>` / `<b>` 显式字重**：浏览器默认 `font-weight: bold`（=700）可精确命中 MiSans 700 字重。必须在 CSS 中显式设置 `strong, b { font-weight: var(--font-weight-bold) }`（定义于 `src/styles/base.css`）。

#### 3.1.2 抗锯齿策略

| 平台 | CSS 属性 | 值 | 策略 |
| --- | --- | --- | --- |
| Windows / macOS | `-webkit-font-smoothing` | `antialiased` | 灰度抗锯齿 |
| Firefox macOS | `-moz-osx-font-smoothing` | `grayscale` | 灰度 |
| 全平台 | `text-rendering` | `optimizeLegibility` | 优先连字与字距 |

> **强制灰度的依据**：HiDPI 屏幕（缩放 ≥125%）上，子像素渲染（ClearType）会造成 MiSans 中文笔画粗细明显不均、边缘出现彩色拖影。灰度抗锯齿消除子像素色散，笔画均匀一致。

### 3.2 场景化排版规范

| 使用场景 | CSS 类 | 字号 | 字重 | 行高 | 颜色 |
| --- | --- | --- | --- | --- | --- |

## 5. 阴影与厚度体系（V4.0 核心）

### 5.1 三层阴影总模型

抽象拟物「亚克力板」的物理体积由 **三层箱阴影** 同构表达，任何"板"类组件（卡片、按钮、标签、导航板、页脚、代码块、表格、引用块、下拉、Pager 卡）皆复用该模型：

| 层 | 作用 | 形态 |
| --- | --- | --- |
| **L1 切边厚度** | 板边自身的物理厚度（右下受光） | 无模糊硬边偏移（`dx dy 0 0 color`） |
| **L2 环境柔影** | 板子悬空于背景上方的柔影 | 含模糊半径、偏右下（`dx dy blur 1px`） |
| **L3 内嵌暗边** | 光源被板体遮挡产生的内嵌暗面 | `inset dx dy blur 0`，位于左上侧 |

### 5.2 板级厚度标尺

几何参数按**板级**划分，同一板级内明暗只换色谱、不动几何（V4.0 修复了几何漂移）：

| 板级 | L1 切边 | L2 柔影（暗色 α / 亮色 α） | L3 内嵌 | 典型组件 |
| --- | --- | --- | --- | --- |
| **板**（Plate） | `4px 4px 0 0` | `10px 8px 6px 1px`（0.30 / 0.10） | `inset 5px 5px 3px 0`（0.15 / `bg65+accent35`） | 卡片、页脚、Navbar、下拉外层、表格、引用块、Pager 卡、`.plate` |
| **按钮**（Button） | `2px 4px 0 0` | `6px 10px 2px 0`（0.30 / 0.12） | `inset 2px 4px 2px 0` | `.btn-primary` / `.btn-outline` |
| **小型控件**（Control） | `1px 2px 0 0` | `2px 3px 4px 0`（0.67 / 0.33） | `inset 1px 2px 1px 0` | `.tag`、.theme-toggle、行内 code、TOC 高亮滑块、步骤圆圈 |
| **凹槽**（Groove） | `2px 4px 3px 0` | `inset 4px 6px 0 0` 硬内嵌 + `inset -2px -3px 8px` 散射 | —（本身即凹面） | 导航凹槽、语言下拉 ul、文档树章节、TOC 分组 |

> **统一规则**：
> 1. 一个组件若复用"板"级，L1/L2/L3 必须采用上表数值，不得自行微调（历史漂移见 §12 修复记录）。
> 2. 按钮的 L2 α（暗色 0.30）此前文档误写为 0.67，以代码为准（0.30）；小型控件 0.67 保留（小体积需要更强接触阴影）。
> 3. **明暗几何同构**：亮色模式的 L1/L2/L3 偏移、模糊与暗色**完全相同**，仅颜色/α 切换（亮色整体弱化：柔影 α 0.10~0.33）。

### 5.3 一级阴影变量

| CSS 变量 | 暗色值 | 亮色值 | 用途 |
| --- | --- | --- | --- |
| `--shadow-near` | `0 2px 4px rgba(0,0,0,0.5)` | `0 2px 4px rgba(0,0,0,0.06)` | 头像、navbar logo |
| `--shadow-far` | `0 12px 28px rgba(0,0,0,0.5), 0 4px 12px rgba(0,0,0,0.3)` | `0 12px 28px rgba(0,0,0,0.1), 0 4px 12px rgba(0,0,0,0.06)` | hover 抬起、下拉菜单、代码块悬浮 |
| `--shadow-embed` | `inset 0 1px 3px rgba(0,0,0,0.4)` | `inset 0 1px 3px rgba(0,0,0,0.06)` | 内凹元素、凹槽轨道 |

## 6. 材质管线：不透明磨砂亚克力板

### 6.1 物理模型

光源从偏上方（160deg）入射，在亚克力板表面产生：左上内嵌暗边（L3）、右下切边聚光（L1）、右下外露厚度、环境柔影（L2）。

```
光源方向：偏上方入射（160deg）
         ▲ 高光（::after, 左上最亮）
  ┌──────┐
  │ ╲    │ ← 左上内嵌暗边 (L3, 光被板体吸收)
  │  ╲   │
  │   ╲  │ ← 右下切边聚光 (L1, 光穿透板体在切边散射)
  └──────┘
       ██ ← 右下外露厚度 (亮 cut edge)
  ░░░░░░░░ ← 环境柔影 (L2, 偏右下)
```

### 6.2 材质变量

| CSS 变量 | 暗色值 | 作用 |
| --- | --- | --- |
| `--edge-highlight` | `inset 0 1px 0 rgba(255,255,255,0.08)` | 顶边高光 |
| `--edge-shadow` | `inset 0 -1px 0 rgba(0,0,0,0.12)` | 底边阴影 |
| `--groove-bg` | `base-bg 60% + primary-bg` 混合 | 凹槽轨道背景 |
| `--groove-inset` | `inset 0 1px 3px rgba(0,0,0,0.25)` | 凹槽内嵌阴影 |

### 6.3 暗色/亮色技术路线差异

| | 暗色模式 | 亮色模式 |
| --- | --- | --- |
| 基底 | 实色深灰（`--clr-primary-bg`） | 实色暖黄（`bg 97% + accent 3%`） |
| 噪点 | SVG 灰度噪点 × `overlay` 混合 + `contrast(8.0)` | SVG 噪点直接在滤镜中 tint 着色为黄色系（`mix-blend-mode: normal`，无滤镜） |
| 高光 | 白色微量渐变（text 8~12%，opacity 0.25~0.5） | 纯白强高光（opacity 0.75） |
| 切边色 | `text 20%` | `bg 94% + accent 6%` |
| 内嵌暗边 | `rgba(0,0,0,0.15)` | `bg 65% + accent 35%` |
| 原理 | 低对比度克制 | 人眼对浅色 alpha 不敏感 → 实色全量覆盖 |

### 6.4 噪点 SVG 参数标准

| 路径 | viewBox | baseFrequency | octaves | tile | 混合 |
| --- | --- | --- | --- | --- | --- |
| 暗色板级/表格/块引用 | 256 | 0.19 | 3 | 120px | overlay + contrast(8.0), opacity 0.25 |
| 暗色按钮/滑块/内联 code | 128 | 0.42 | 3 | 70px | tint 着色（R 0.78 / G 0.14 / B 0.12） |
| 亮色板级 | 512 | 0.21 | 3 | 200px | normal（tint: R≈G 高、B 低） |
| 亮色按钮/滑块 | 128 | 0.42 | 3 | 70px | normal（tint: 偏橙） |
| 页面砂纸（body） | — | 1.5 | 3 | 100px | overlay, opacity 0.18 |

> 新组件不得自创第 5 种噪点参数；必须从上述清单中选择。

## 8. 根画布背景设计

`body` 背景由 3 层组成：

| 层 | 内容 | 作用 |
| --- | --- | --- |
| Layer 1 | 底色 `var(--clr-base-bg)` | 页面基础色 |
| Layer 2 | 希尔伯特曲线分形纹理 | 低频结构，打破纯色单调 |
| Layer 3 | 砂纸噪点（SVG feTurbulence） | 高频颗粒，模拟板材微纹理 |

**希尔伯特曲线（Layer 2）**：`src/scripts/hilbert.ts` 生成第 5 阶希尔伯特曲线（1024 个顶点），渲染为 SVG `<path>`。pattern 尺寸 280×280px，旋转 45°。曲线描边色 `#242424`（亮色 `#EDE4D6`），opacity 0.55，stroke-width 7，linecap round。

**砂纸噪点（Layer 3）**：覆盖 `body::before` 的默认圆点纹理（24px 网格，opacity 0.15）：SVG `feTurbulence` (baseFrequency=1.5, 3 octaves) + `feColorMatrix` tint 着色，100px tile，opacity 0.18。

**代码块 Gosper 曲线**：`src/scripts/code-bg.ts` 生成 5 阶 Gosper（Flowsnake）曲线，晶格 tile 拼接（280px），描边色 `#242424`（亮色 `#EDE4D6`），opacity 0.35/0.40。

## 11. 国际化与 RTL（概览）

- **10 种语言**：`zh-cn`（默认）、`en-us`、`ja-jp`、`ko-kr`、`ar-sa`、`es-es`、`fr-fr`、`pt-pt`、`ru-ru`、`de-de`
- **路由策略**：默认语言无前缀 `/`，其他语言 `/<locale>/`（`[locale]` 动态路由）
- **RTL 支持**：`ar-sa` 自动设置 `dir="rtl"`，全局布局由浏览器 RTL 引擎处理
- **语言切换器**：导航栏右侧下拉菜单，垂直滑块指示，选中项高亮
- **多语言 SEO**：`<link rel="alternate" hreflang="...">` + 规范 URL + 各语言独立 RSS
- **Middleware**：`src/middleware.ts` 将大写 locale（`/en-US/`）301 重定向至规范小写格式（`/en-us/`）
- **物理动效的 RTL 语义**（详见动效规范）：阴影方向/滑块位移在 RTL 下保持物理直觉，只允许视觉镜像（如 hover 抬升），不允许方向性翻转导致「光从右下入射」的别扭感
