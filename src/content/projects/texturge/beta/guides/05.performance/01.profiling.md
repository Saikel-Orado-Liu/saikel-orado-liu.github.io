# 性能分析与调试

Texturge 是 CPU 驱动的动画求值系统。21 通道逐字形逐图层曲线计算构成了主要的性能开销。了解热点路径与分析方法有助于在高负载场景下保持帧率。

## 性能模型

### 曲线求值成本估算

每帧的动画求值开销近似为：

```
总求值次数 ≈ 字形数 × 图层数 × 21 通道
```

典型场景示例：

| 场景 | 字形数 | 图层数 | 每帧求值次数 |
|------|--------|--------|-------------|
| 简单打字机 | 50 | 1 | ~1,050 |
| 多图层标题 | 30 | 3 | ~1,890 |
| 富文本直播弹幕 | 100 | 3 | ~6,300 |
| 极端场景（3 阶段全） | 100 | 3 | ~18,900 |

> NOTE
>
> 三阶段系统意味着 Intro/Default/Outro 各有独立的 `FBakedStage`。当前播放阶段仅对该阶段的曲线求值，不会同时计算所有阶段。

### 热点路径

`FBakedGlyph::Evaluate()` 是动画求值的核心热点路径：

1. `FBakedGlyph::Evaluate(float StageTime, float TotalDuration, FGlyphAnimationState& OutState)` 入口。
2. 内部调用 `HasStarted()` / `HasFinished()` 进行提前退出检查 —— 未开始或已结束的字形跳过全部曲线求值。
3. 遍历 `Layers` 数组，调用每个 `FPerLayerCurves::Evaluate()`。
4. `FPerLayerCurves::Evaluate()` 对 21 个通道逐通道执行 `FRichCurveKey` 数组插值。

**性能关键点**：
- `HasStarted()` / `HasFinished()` 提前退出大幅减少不可见字形的求值开销。
- `FRichCurveKey` 数组在编译时预烘焙 —— 运行时无曲线解析开销，仅做数组插值。
- 编译在编辑器完成，运行时零烘焙开销。

## Unreal Insights 集成

### 启动 Trace

1. 启动 Unreal Insights 或通过控制台命令开始录制：
   ```
   Trace.Start
   ```

2. 运行动画场景至少 5 秒以收集足够样本。

3. 停止录制：
   ```
   Trace.Stop
   ```

4. 在 Unreal Insights 中打开生成的 `.utrace` 文件。

### 关键 Trace 通道

在 Insights 中按以下名称过滤以定位 Texturge 相关开销：

- `Texturge::TickAnimation` — `UTextAnimationStageController::TickAnimation()` 总耗时
- `Texturge::EvaluateGlyph` — `FBakedGlyph::Evaluate()` 逐字形耗时
- `Texturge::OnPaint` — `UAnimatedTextBlock::OnPaint` 渲染耗时
- `Texturge::Compile` — 编辑器端编译耗时（非运行时）

### 分析优先级

1. 先检查 `TickAnimation` 总耗时占比。若超过 2ms/帧，深入分析。
2. 展开 `EvaluateGlyph` 查看各字形耗时分布 —— 关注是否有特定字形耗时异常。
3. 若 `OnPaint` 耗时高，检查是否同时渲染了大量 `UAnimatedTextBlock` 控件。

## 控制台统计命令

Texturge 提供内置统计命令。在控制台中输入：

```
stat Texturge
```

显示的统计项包括：
- 活跃的 `UAnimatedTextBlock` 控件数量
- 当前正在求值的字形总数
- 各字形的平均 `Evaluate()` 耗时（微秒）
- 当前帧的 `TickAnimation()` 总耗时

## 指纹缓存

### 编译缓存机制

`FAnimationCompiler::ComputeTextFingerprint()` 和 `ComputeBlueprintFingerprint()` 使用 MD5 哈希：

1. 每次编译前检查文本与蓝图的 MD5 指纹。
2. 两个指纹均未变化时，跳过烘焙直接复用缓存的 `FBakedAnimation`。
3. 只有文本内容或蓝图资产变化时才触发重新编译。

### 缓存失效时机

- 文本内容改变 → 文本指纹变化 → 触发重新烘焙
- `UGlyphAnimation` 轨道修改 → 蓝图指纹变化 → 触发重新烘焙
- `UGlyphAnimationLayer` 参数调整 → 蓝图指纹变化 → 触发重新烘焙

运行时可通过 `UTextAnimInstance::NeedsRebake()` 检查当前缓存是否有效。
