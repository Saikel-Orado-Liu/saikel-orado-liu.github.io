Follow these practices to maintain high frame rates and low memory in complex scenes.

## 1. Player Object Pool

Avoid frequent creation and destruction of `UTexturgePlayer`. Use the built-in object pool:

```cpp
UTexturgePlayer* Player = UTexturgeSubsystem::Get()->AcquirePlayer();
Player->Init(Asset);
Player->Play();
// ...
Player->Stop();
UTexturgeSubsystem::Get()->ReleasePlayer(Player);
```

Default pool capacity is 32. Adjust via `UTexturgeSettings::PlayerPoolSize`.

## 2. LOD Strategy

Texturge supports three LOD levels that auto-degrade based on screen coverage:

| LOD | Screen % | Behavior |
|-----|----------|----------|
| 0   | > 10%    | Full-resolution, per-character animation |
| 1   | 2-10%    | Half-resolution, simplified curves |
| 2   | < 2%     | Static texture, animation disabled |

```cpp
Player->SetLODBias(1);  // force LOD1
```

## 3. Frustum Culling

`bEnableFrustumCulling` is enabled by default, pausing rendering when the text bounds fully leave the viewport. Distance culling is also supported in World Space mode:

```cpp
Player->MaxRenderDistance = 5000.0f;  // don't render beyond 50m
```

## 4. Atlas Texture Streaming

For multi-atlas fonts, enable `bStreamAtlases` to load atlases on demand at runtime, avoiding a large one-time VRAM spike:

```cpp
FontAsset->bStreamAtlases = true;
FontAsset->StreamingPoolSize = 128;  // max concurrently resident atlases
```

## 5. Batch Rendering

Players sharing the same material and font should merge into the same render batch. Set `BatchGroup` to the same value for automatic batching:

```cpp
Player->BatchGroup = TEXT("UI_Frontend");  // auto-batched within group
```
