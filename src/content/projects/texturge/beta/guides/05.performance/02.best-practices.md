# 性能最佳实践

遵循以下实践可在复杂文本动画场景中保持稳定帧率与低 CPU 开销。

## 1. 控制字形与图层规模

### 字形数量

每增加一个字形，每帧增加 `图层数 × 21` 次曲线求值。建议：

- **简单 UI 文本（标签、按钮）**：< 30 字形
- **标题动画**：< 80 字形
- **长文本（对话框、说明）**：考虑分段，每段 < 150 字形
- **极端场景（直播弹幕等）**：控制在 500 字形以内并配合控件池化

### 图层数量

每增加一个图层，每帧每个字形增加 21 次曲线求值。建议：

- **单效果动画**：1 图层
- **标准多效果**：2–3 图层
- **复杂动画**：≤ 5 图层

超过 5 图层时考虑在 `BuildDefaultAnimation` 中将多个效果合并到同一图层，或使用 `Multiply` 模式叠加调制效果而非独立图层。

## 2. 预编译策略

所有动画曲线在编辑器 Compile 时完成计算，运行时零烘焙开销：

1. 确保发布前对所有 `UTextAnimationBlueprint` 执行 Compile。
2. 编译后的 `FBakedAnimation` 数据嵌入 `UTextAnimationBlueprintGeneratedClass`。
3. 运行时仅执行 `FBakedGlyph::Evaluate()` —— 无曲线解析、无字体处理、无烘焙开销。

## 3. UAnimatedTextBlock 控件池化

> TIP
>
> 控件池化可显著降低 GC 压力，尤其在高频创建销毁动画文本的场景（如弹幕、通知）。建议在 Tick 中批量获取与归还控件。

频繁创建/销毁 `UAnimatedTextBlock` 会产生 GC 压力。建议实现控件池：

```cpp
// 获取控件
UAnimatedTextBlock* Widget = WidgetPool->Dequeue();

// 重置控件状态
Widget->StopAnimation();
Widget->SetText(NewText);

// 播放入场动画
Widget->PlayAnimation();

// 使用完毕后归还
Widget->StopAnimation();
WidgetPool->Enqueue(Widget);
```

池大小根据同时显示的文本控件峰值数量设定，通常 32–64 个即可满足 UI 场景需求。

## 4. 利用提前退出优化

`FBakedGlyph::Evaluate()` 内置 `HasStarted()` 与 `HasFinished()` 检查和 `GetEffectiveDuration()` 有效时长检测：

- **调度延迟较大的字形**：延迟时间到达前直接跳过全部求值。
- **已完成的字形**：`HasFinished()` 返回 true 后不再求值。
- **`IsCurvesEmpty()` 检查**：空曲线数据直接跳过。

### 设计建议

在 `UGlyphAnimationLayer` 中合理配置调度延迟与跳过标志，最大化提前退出比例：

```cpp
Layer->SetAllGlyphDelay(0.05f);  // 每个字形延迟 0.05s —— 大部分时间仅活跃 2-3 个字形
Layer->SkipAllWhitespace(true);   // 空白字符不参与动画
```

## 5. 使用 UTextAnimationDataAsset

富文本场景下，通过 `UTextAnimationDataAsset` 将标签映射集中在 DataAsset 中管理，避免运行时字符串匹配开销：

1. 创建 `UTextAnimationDataAsset`，配置 `FAnimationEntry` 条目。
2. 每个条目将富文本标签名映射到 `UTextAnimationBlueprint`。
3. 通过 `TSoftObjectPtr` 异步加载蓝图资产，避免一次性全量加载。
4. 每个条目支持 6 组参数复写 Map（Float / Int / Bool / Vector / Color / Vector2D），按需传入而不需额外蓝图实例。

## 6. 合批建议

`UAnimatedTextBlock` 继承自 UMG 标准文本控件，渲染由 Slate 自动合批：

1. 同字体、同材质的文本自动合批为少量 Draw Call。
2. 避免在动画中频繁修改 `Font` 属性 —— 字体变更会破坏合批。
3. 若需多字体效果，使用 Composite Font 而非多个 `UAnimatedTextBlock` 叠加。

## 7. 三阶段优化

`FBakedAnimation` 的三阶段（Intro/Default/Outro）独立存储，当前播放阶段仅对该阶段的数据求值：

1. 将长动画拆分为 Intro（短入场）+ Default（主体循环）+ Outro（短退场）。
2. Default 阶段可配置 `bLoop` 实现持续循环，避免烘焙超长动画。
3. 使用 `bCrossfadeEnabled` 平滑切换而非瞬时跳变，但注意跨淡期间两份数据同时求值。
