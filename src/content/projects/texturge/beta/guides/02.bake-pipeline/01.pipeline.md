# 烘焙管线概览

Texturge 的烘焙管线将 `UTextAnimationBlueprint` 与指定文本编译为预计算的 `FBakedAnimation` 数据。整个过程在编辑器 Compile 时完成，运行时零烘焙开销。

> NOTE
>
> Texturge 不存在字体→SDF 纹理烘焙管线。动画编译管线处理的是逐字形曲线数据，不涉及 GPU 纹理生成。

## 管线入口

`FAnimationCompiler::BakeAllStages()` 是烘焙管线的唯一入口点：

```cpp
TUniquePtr<FBakedAnimation> FAnimationCompiler::BakeAllStages(
    UTextAnimationBlueprint* Blueprint,
    const FString& Text
);
```

该函数是静态方法，返回包含 Intro/Default/Outro 三个阶段的 `FBakedAnimation`。

## 管线阶段

### 第一阶段：构建调度信息

1. `FAnimationCompiler::BuildScheduleInfos(Text)` 将文本解析为 `TArray<FGlyphScheduleInfo>`。
2. 对每个字符进行分类（可见字形、空白字符、组合字符等）。
3. 计算每个字形的默认延迟值与起始时间偏移。

### 第二阶段：蓝图事件烘焙

1. 获取编译后生成的 `UTextAnimationBlueprintGeneratedClass` 的 `CDO`（`UTextAnimInstance`）。
2. 调用 CDO 的 `BuildDefaultAnimation(GlyphCount, Text)` 蓝图事件。
3. `BuildDefaultAnimation` 的默认 C++ 实现执行以下流程：

```
CreateLayer() → CreateFactory() → AddLayer() → Bake()
```

4. 开发者可在子类中覆盖 `BuildDefaultAnimation` 以实现完全自定义的烘焙逻辑。

### 第三阶段：工厂烘焙

`UGlyphAnimationFactory::Bake()` 执行核心烘焙：

1. **逐层烘焙** — 对工厂中的每个 `UGlyphAnimationLayer` 调用 `BakeStageWithCurves` 生成 `FPerLayerCurves` 数据。
2. **曲线覆盖** — 应用用户通过 `GlyphCurveOverrides` 指定的逐字形曲线修正。
3. **逐字形逐层组装** — 对每个字形调用 `FBakedGlyph::AddLayer()` 将图层曲线数据写入目标数据结构。
4. **后处理** — 应用计划表延迟调整、曲线微调（缩放/偏移/抖动）等后处理步骤。

### 第四阶段：组装最终输出

1. `FAnimationCompiler` 将烘焙结果组装为 `FBakedAnimation`，分别填充 Intro、Default、Outro 三个阶段的 `FBakedStage`。
2. 每个 `FBakedStage` 包含完整的 `TArray<FBakedGlyph>`，每个 `FBakedGlyph` 含该字形所有图层的 `FPerLayerCurves`。

## 指纹缓存

为避免无变化的重复编译，Texturge 使用两阶段指纹校验：

1. **文本指纹** — `FAnimationCompiler::ComputeTextFingerprint(Text)` 基于输入文本计算 MD5 哈希。
2. **蓝图指纹** — `FAnimationCompiler::ComputeBlueprintFingerprint(BP)` 基于蓝图资产内容计算 MD5 哈希。

当两个指纹均未变化时，跳过烘焙直接使用缓存数据。`UTextAnimInstance::NeedsRebake()` 在运行时检查缓存是否有效。
