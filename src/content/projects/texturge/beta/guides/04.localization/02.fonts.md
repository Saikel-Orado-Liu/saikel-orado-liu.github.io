# 多语言字体与 CJK 支持

多语言文本动画的核心挑战在于 CJK（中日韩）字符的正确分割与字体回退。Texturge 通过 `FCharBreakIterator` 与 Unicode 工具类解决了这些问题。

> NOTE
>
> Texturge 不存在 `UTexturgeFontAsset`、字体图集烘焙或 SDF 字形缓存。字符渲染由 UMG/Slate 的标准字体管线处理，插件仅负责动画曲线逻辑。

## CJK 字符分割

### 为什么 CJK 需要特殊处理

- CJK 字符不使用空格分隔词语，每个字符独立表意。
- 拉丁字母语言的换行规则（按空格分词）无法直接应用于中文。
- 动画中的逐字形索引必须正确反映 CJK 文本的实际字符边界。

### FCharBreakIterator

`FCharBreakIterator` 是 CJK 感知的断字迭代器，用于正确分割 CJK 文本为可动画的字符序列：

```cpp
FCharBreakIterator Iterator(Text);
Iterator.MoveToNext();
int32 CharStart = Iterator.GetStartPos();
int32 CharEnd = Iterator.GetEndPos();
```

其主要功能：
1. 按语义边界分割 CJK 字符（不按字节数简单切分）。
2. 识别全角/半角字符差异。
3. 处理组合字符（变音符号与基字符的组合）。
4. 正确处理代理对（Surrogate Pairs）与 emoji。

### 与传统方法对比

| 方法 | 拉丁字符 | CJK 字符 |
|------|----------|----------|
| 按字节/UTF-16 码元切分 | 正确 | 可能错误（代理对） |
| `FCharBreakIterator` | 正确 | 正确 |

## 字体回退

Texturge 不直接管理字体资产，而是依赖 UMG 的字体回退机制：

1. 在 `UAnimatedTextBlock` 的 `Font` 属性中设置主字体。
2. UE5 的 Composite Font 系统自动处理缺失字符的回退。
3. 对于覆盖多语言的复杂场景，使用 Composite Font 的 Sub-Font 功能分别指定各书写系统的字体。

## Unicode 工具类

Texturge 包含 Unicode 字符分类工具，用于动画逻辑中的字符判断：

- 字母、数字、标点、空白字符分类
- CJK 统一汉字范围判断
- RTL（从右到左）字符检测
- 组合字符与变音符号识别

这些工具在 `BuildScheduleInfos()` 中被用于正确分类每个字符，从而决定其调度行为（是否跳过、使用何种延迟等）。

> TIP
>
> 对于覆盖多语言的项目，使用 Composite Font 的 Sub-Font 功能分别为各书写系统指定字体，而非依赖多控件叠加。

## 测试 CJK 动画

### 推荐测试文本

在 `STextAnimationDesignerView` 的预览文本框中输入以下混合文本以验证 CJK 支持：

```
English 日本語 한국어 中文 العربية हिन्दी
Emoji: 🎮🎯✨
全角：ＡＢＣＤ１２３４
```

### 验证检查项

1. **字符计数正确** — 每个 CJK 字被计为一个独立字形。
2. **调度延迟正确** — 逐字动画节奏均匀，不因字符编码长度变化而跳帧。
3. **代理对处理** — Emoji 正确显示为单个字符，不分裂为两个字符。
4. **RTL 文本** — 阿拉伯文从右到左正确排列。
