Multi-language projects must handle missing glyphs in primary fonts. Texturge provides a font fallback chain that automatically searches for glyphs in backup fonts.

## Configuring the Fallback Chain

1. Open your `UTexturgeFontAsset` and locate the **Fallback Fonts** array.
2. Add backup fonts in priority order — lower array indices have higher priority.

```cpp
FontAsset->PrimaryFont = NotoSansRegular;
FontAsset->FallbackFonts.Add(NotoSansCJK);       // CJK fallback
FontAsset->FallbackFonts.Add(NotoSansArabic);     // Arabic fallback
FontAsset->FallbackFonts.Add(NotoSansDevanagari); // Devanagari fallback
```

## CJK Font Strategy

CJK character sets contain thousands of glyphs. Baking them all produces enormous atlases. Recommended strategy:

1. **Bake on Demand** — Use `FromStringTable` mode to only bake CJK characters actually used in your project.
2. **Separate Atlases** — Manage Latin and CJK font atlases separately. Use 512×512 for Latin, 4096×4096 for CJK.
3. **Runtime Streaming** — Enable `bStreamGlyphs` to dynamically load uncached glyphs at runtime.

```cpp
CJKConfig.CharacterSet = ETexturgeCharSet::FromStringTable;
CJKConfig.AtlasSize = 4096;
CJKConfig.bStreamGlyphs = true;  // load unbaked glyphs on demand
```

## Font Metric Compatibility

Different fonts may have different metric parameters (Ascender, Descender, Line Gap). Enable `bNormalizeMetrics` to auto-align baselines across all fallback fonts:

```cpp
FontAsset->bNormalizeMetrics = true;
FontAsset->BaseMetricsFont = PrimaryFont;  // align against primary font
```

## Testing the Fallback Chain

Use the **Texturge Preview** panel in the editor to enter test text with mixed-language characters and verify the fallback chain works correctly:

```
English 日本語 한국어 العربية हिन्दी
```
