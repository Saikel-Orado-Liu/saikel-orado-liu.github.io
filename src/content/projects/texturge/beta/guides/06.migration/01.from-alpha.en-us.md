Texturge Beta introduces architectural improvements and API changes. This guide helps you migrate smoothly from the Alpha version.

## Key Changes

1. **Asset Renames** — `UTexturgeAnimAsset` → `UTexturgeAsset`, `UTexturgeFontResource` → `UTexturgeFontAsset`.
2. **Layer System Rewrite** — Upgraded from single-layer fixed properties to `FTexturgeLayerConfig` array-driven design.
3. **Bake Pipeline Separation** — Baker is now a standalone module separate from Runtime; old inline bake functions are removed.
4. **Player API Change** — `FTexturgePlayerHandle` replaced by `UTexturgePlayer` UObject reference.

## Migration Steps

1. **Back up your project** before upgrading the plugin.
2. **Replace the plugin** — remove the Alpha plugin folder and drop in Beta.
3. **Regenerate project files** — right-click `.uproject` and select **Generate Visual Studio project files**.
4. **One-click asset migration** — after opening the editor, right-click old assets and select **ScriptedAssetActions > Migrate to Texturge Beta**. The system auto-converts asset types and preserves all settings.
5. **Re-bake all fonts** — due to atlas format changes, all fonts must be re-baked. Right-click `UTexturgeFontAsset` and select **Rebake Font Atlas**.
6. **Update custom C++ code** — update API references in your code.

## API Mapping

| Alpha API | Beta API |
|-----------|----------|
| `PlayerHandle->SetText(TEXT("Hello"))` | `Player->SetText(TEXT("Hello"))` |
| `AnimAsset->Layers[0].Color` | `AnimAsset->GetLayer(0)->Color` |
| `FontResource->BakeInline()` | `BakerSubsystem->BakeFont(Config)` |
| `PlayerHandle.IsValid()` | `IsValid(Player)` |

## FAQ

**Q: Animation looks different after migration?**  
A: Beta SDF threshold calculation has been adjusted. Check your layer `SDFThreshold` values — typically reduce by 0.05–0.1.

**Q: Can I downgrade old assets back to Alpha?**  
A: No. Migration is one-way. Always back up before migrating.
