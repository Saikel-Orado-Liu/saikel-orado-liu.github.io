# Rich Text Tags Reference

Texturge's rich text tag system supports embedding custom tags in text to apply different text animation blueprints to different paragraphs.

## Tag Syntax

### Basic Open/Close Tags

```
<tagname>text content</>
```

```xml
<typewriter>This text uses typewriter effect</>
```

### Using the id Attribute

```
<anim id="tagname">text content</>
```

```xml
<anim id="bounce">This text bounces in</>
```

When using `anim id` syntax, the `id` value takes priority over the tag name. If both exist, `id` wins.

### Self-Closing Tags

```
<tagname />
```

```xml
<img id="icon_sword" />
```

Self-closing tags have no content and are typically used for decorators (like images).

### Attribute Tags

```
<tagname attr="value" />
```

```xml
<delay time="0.5" />
```

### Explicit Close

```
<tagname>text</tagname>
```

```xml
<wave>Wave effect text</wave>
```

## Tag-to-DataAsset Matching

Tag names (or `anim id`) must match entries in `TextAnimationDataAsset`:

| Tag Usage | DataAsset Entry Name | Match Result |
|-----------|---------------------|-------------|
| `<typewriter>` | `typewriter` | Match |
| `<anim id="typewriter">` | `typewriter` | Match (id priority) |
| `<Typewriter>` | `typewriter` | No match (case-sensitive) |
| `<typewriter>` | `Typewriter` | No match |

> [!IMPORTANT]
> Tag matching is strictly case-sensitive. `<Typewriter>` and `<typewriter>` are different tags.

## Escape Sequences

| Sequence | Character |
|----------|-----------|
| `&lt;` | `<` |
| `&gt;` | `>` |
| `&amp;` | `&` |

```xml
<typewriter>Use &lt;tag&gt; to represent tags</>
```

Rendered result: `Use <tag> to represent tags`

## Tag Nesting

Tags support nesting, with inner tags affecting text within their range:

```xml
<typewriter>
  This is typewriter effect
  <bounce>This bounces within the typewriter</bounce>
  Back to typewriter
</typewriter>
```

Nesting rules:
- Inner animation tags override outer animation tags
- Style tags (like `<Large>`) stack rather than override
- Closing `</>` closes the most recently opened tag

## Mixing Standard Styles

Texturge animation tags can be mixed with UMG rich text style tags:

```xml
<typewriter><Large>Large typewriter</></> <Small>Small text</>
```

Supported style tags depend on the configured `StyleSet` (standard UMG RichTextBlock mechanism).

## Render Node Types

`FRenderTreeBuilder` classifies the parsed tag tree into four render node types:

| Type | Enum | Description |
|------|------|-------------|
| AnimationLayer | `ERenderNodeType::AnimationLayer` | Animation layer node (has matching DataAsset entry) |
| StyleLayer | `ERenderNodeType::StyleLayer` | Style layer node (standard UMG style) |
| TextContent | `ERenderNodeType::TextContent` | Plain text content node |
| Decorator | `ERenderNodeType::Decorator` | Decorator node (images, etc.) |

## EntryIndex Matching Priority

1. **id attribute**: `<anim id="typewriter">` → match DataAsset by `id` value
2. **Tag name fallback**: `<typewriter>` → match DataAsset by tag name
3. **No match**: Tag treated as style tag (StyleLayer) or ignored

## Examples

### Basic Usage

```xml
<typewriter>Hello world</>
```

### Multi-Animation Blend

```xml
<typewriter>Normal text</> <bounce>Bouncing text</> <wave>Wavy text</>
```

### Nested Effects

```xml
<typewriter>
  Typing...
  <shake>This part is shaking!</shake>
  Back to normal
</typewriter>
```

### Mixed Styles

```xml
<typewriter><Title>Animated title</></>

<normal><Bold>Bold</Bold> and <Italic>italic</Italic> text</>
```

### Image Decorator

```xml
<typewriter>Obtained: <img id="item_sword"/> Iron Sword</>
```

## Parser Error Tolerance

`FTagParser` has the following error tolerance:

| Bad Format | Handling |
|------------|----------|
| Unclosed tag `<tag>` | Treated as plain text |
| Invalid escape | Keep original chars |
| Extra `</>` | Ignored |
| Empty tag `<>` | Ignored |
| Attribute-only tag | Keep tag text |
