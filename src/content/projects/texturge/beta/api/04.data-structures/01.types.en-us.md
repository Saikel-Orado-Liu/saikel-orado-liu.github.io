Texturge defines a set of data structures for passing animation state between runtime, editor, and Blueprint. They are classified into enums, USTRUCTs, and non‑USTRUCTs based on whether they belong to the UObject inheritance chain.

## Enumeration Types

### EAnimationStage

```cpp
UENUM(BlueprintType)
enum class EAnimationStage : uint8
{
    Intro           UMETA(DisplayName = "Intro"),
    Default         UMETA(DisplayName = "Default"),
    Outro           UMETA(DisplayName = "Outro"),
    None            UMETA(DisplayName = "None"),
    GlyphEditor     UMETA(DisplayName = "Glyph Editor")
};
```

| Value | Description |
|:---|:---|
| `Intro` | Entrance stage, glyphs appear one by one |
| `Default` | Default stage, looping animation after full text reveal |
| `Outro` | Exit stage, glyphs disappear one by one |
| `None` | Null stage, no animation |
| `GlyphEditor` | Editor‑only: glyph editor mode |

## USTRUCTs

### FAnimationEntry

Row data structure for `UTextAnimationDataAsset`.

```cpp
USTRUCT(BlueprintType)
struct FAnimationEntry : public FTableRowBase
{
    FString TagName;
    TSoftObjectPtr<UTextAnimationBlueprint> Type;
    TMap<FName, float>          FloatOverrides;
    TMap<FName, int32>          IntOverrides;
    TMap<FName, bool>           BoolOverrides;
    TMap<FName, FVector>        VectorOverrides;
    TMap<FName, FLinearColor>   ColorOverrides;
    TMap<FName, FVector2D>      Vector2DOverrides;
};
```

| Field | Type | Description |
|:---|:---|:---|
| `TagName` | `FString` | Rich‑text tag name (e.g. `"shake"` for `<anima=shake>`) |
| `Type` | `TSoftObjectPtr<UTextAnimationBlueprint>` | Soft reference to the linked animation blueprint |
| `FloatOverrides` | `TMap<FName, float>` | Float parameter overrides |
| `IntOverrides` | `TMap<FName, int32>` | Int parameter overrides |
| `BoolOverrides` | `TMap<FName, bool>` | Bool parameter overrides |
| `VectorOverrides` | `TMap<FName, FVector>` | Vector parameter overrides |
| `ColorOverrides` | `TMap<FName, FLinearColor>` | Color parameter overrides |
| `Vector2DOverrides` | `TMap<FName, FVector2D>` | Vector2D parameter overrides |

    float ShadowColorA;

## Data Structure Relationship Diagram

```
UTextAnimationBlueprint
    ├── GlyphAnimations: TArray<UGlyphAnimation*>
    │       └── MovieScene (UMovieScene*) + Tracks
    ├── Tracks: TArray<FTextAnimationTrack>
    └── [Compile] → UTextAnimationBlueprintGeneratedClass
            └── → FAnimationCompiler::BakeAllStages
                    └── FBakedAnimation
                        ├── IntroStage  → FBakedStage
                        ├── DefaultStage → FBakedStage
                        └── OutroStage  → FBakedStage
                            └── Glyphs: TArray<FBakedGlyph>
                                ├── Layers: TArray<FPerLayerCurves>
                                │       └── [24 FRichCurveKey arrays]
                                └── BlendModes: TArray<ETextAnimationBlendMode>

UTextAnimationStageController::EvaluateAllGlyphs
    └── FBakedGlyph::Evaluate(StageTime, Duration)
            └── PerLayer → Evaluate → FGlyphAnimationState
```

## Memory Layout Considerations

- `FBakedAnimation` uses `TUniquePtr` to own individual stages, heap‑allocated with unique ownership
- `FBakedGlyph::Layers` array length varies per glyph; layer count is independent per glyph
- `FPerLayerCurves` is the largest struct — contains 24 `TArray<FRichCurveKey>` fields, each curve holding 0–N keyframes
- `FGlyphAnimationState` is a compact POD — 24 contiguous `float` fields (96 bytes), ideal for stack allocation and SIMD batch processing
- The runtime hot path (`EvaluateAllGlyphs` → `FBakedGlyph::Evaluate`) uses `FGlyphAnimationState` stack variables to avoid heap allocations
