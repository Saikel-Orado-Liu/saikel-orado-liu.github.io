Texturge connects the animation lifecycle to the Blueprint system via delegates and UFUNCTION events.

## Animation Lifecycle Events

### Stage Events (UTextAnimationStageController Delegates)

```cpp
DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(
    FOnStageChanged,
    EAnimationStage, Stage,
    UTextAnimationStageController*, Controller
);
```

| Delegate | Type | Trigger |
|:---|:---|:---|
| `StageStarted` | `FOnStageChanged` | Fires when a new stage begins playback |
| `StageCompleted` | `FOnStageChanged` | Fires when the current stage completes |
| `AllStagesCompleted` | `FSimpleDelegate` | Fires when all three stages (Intro→Default→Outro) have completed |

### Delegate Parameters

| Parameter | Type | Description |
|:---|:---|:---|
| `Stage` | `EAnimationStage` | The stage that triggered the event (Intro/Default/Outro) |
| `Controller` | `UTextAnimationStageController*` | Reference to the controller instance that fired the event |

### Blueprint Binding Steps

1. Get a reference to `UTextAnimationStageController` in the Event Graph
2. Drag off the controller pin → search `Assign Stage Started` / `Assign Stage Completed` / `Assign All Stages Completed`
3. Connect the red event pin to a custom event node
4. In the custom event, access the `Stage` and `Controller` output parameters

**Blueprint wiring example**:

```
[Controller Ref]
    ├── [Assign Stage Started] ──→ [Custom Event: OnIntroStarted]
    │       → [Print String "Intro stage started"]
    │
    ├── [Assign Stage Completed] ──→ [Custom Event: OnStageDone]
    │       → [Branch] (Stage == Intro ? -> Start Default Logic)
    │
    └── [Assign All Stages Completed] ──→ [Custom Event: OnAllDone]
            → [Destroy Widget / Transition Level]
```

## BuildDefaultAnimation (BlueprintNativeEvent)

The most central Blueprint event in `UTextAnimInstance`, allowing the default animation build logic to be overridden in Blueprint.

```cpp
UFUNCTION(BlueprintNativeEvent, Category = "Texturge|Animation")
FBakedAnimation BuildDefaultAnimation(int32 GlyphCount, const FString& Text);
```

| Parameter | Type | Description |
|:---|:---|:---|
| `GlyphCount` | `int32` | Number of glyphs in the text |
| `Text` | `const FString&` | The full text content |
| **Return** | `FBakedAnimation` | Baked animation data containing all three stages (Intro/Default/Outro) |

### Blueprint Override Example

In the Animation Blueprint Event Graph:

1. Right‑click the graph → `Override` → `BuildDefaultAnimation`
2. Add the `Event BuildDefaultAnimation` node
3. Use `BuildScheduleInfos` to build schedule information for the text
4. Configure per‑glyph animation parameters through `UGlyphAnimationLayer` factories
5. Call `Bake()` to produce the `FBakedAnimation`
6. Output the baked data from the Return node

## Variable Change Events (UTextAnimationBlueprint Delegates)

```cpp
FSimpleDelegate OnVariableAdded;
FSimpleDelegate OnVariableRemoved;
FSimpleDelegate OnVariableRenamed;
```

| Delegate | Trigger |
|:---|:---|
| `OnVariableAdded` | Fires when a new parameter variable is added to the animation blueprint variable table |
| `OnVariableRemoved` | Fires when a parameter variable is deleted from the animation blueprint variable table |
| `OnVariableRenamed` | Fires when a parameter variable is renamed |

These delegates are primarily used for internal editor refresh, not gameplay logic.

## BlueprintImplementableEvent Methods

`UTextAnimInstance` provides the following `BlueprintImplementableEvent` methods, implementable in Blueprint without C++ base implementations:

### EvaluateBaked Override

```cpp
UFUNCTION(BlueprintImplementableEvent, Category = "Texturge|Evaluation")
FBakedAnimation EvaluateBaked(const FString& Text);
```

In the default implementation, `EvaluateBaked` checks `NeedsRebake` to decide whether rebaking is needed. A Blueprint override can add custom caching logic or modify the bake process.

### BuildScheduleInfos Override

```cpp
UFUNCTION(BlueprintImplementableEvent, Category = "Texturge|Scheduling")
TArray<FGlyphScheduleInfo> BuildScheduleInfos(const FString& Text, int32 GlyphCount);
```

Allows overriding glyph‑scheduling logic in Blueprint — modifying start delay, skip logic, and scale factors per glyph.

## Event Wiring Best Practices

1. **Bind events after initialization** — Configure delegate bindings after the `Initialize` call to avoid null controller references
2. **Use the Stage parameter to differentiate stages** — Check the `Stage` parameter in `StageStarted` and `StageCompleted` to decide per‑stage gameplay logic
3. **Clean up in AllStagesCompleted** — Release resources, destroy widgets, or trigger level transitions after all animation ends
4. **Use ApplyInstanceOverrides before building** — Apply overrides before `BuildDefaultAnimation`
5. **Cache animation references** — Call `GetAnimationByName` in `BeginPlay` to cache `UGlyphAnimation` references
