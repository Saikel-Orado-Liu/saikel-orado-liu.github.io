# 烘焙管线

烘焙管线是 Texturge Beta 最核心的架构变革——将动画计算从运行时转移到编译期，实现零运行时开销的动画求值。

## 概念

在 Alpha 版本中，动画求值（轨道插值、逐字符参数计算）发生在每帧运行时。Beta 引入了 `FAnimationCompiler`——一个纯函数编译器，在编辑时将 `UTextAnimationBlueprint` + 文本内容预编译为 `FBakedAnimation`。

### 为什么需要烘焙

| 对比 | 运行时求值（Alpha） | 编译期烘焙（Beta） |
|------|---------------------|-------------------|
| 计算位置 | 每帧 Tick | 编辑器编译时 |
| 性能影响 | 随字符数线性增长 | 零运行时开销 |
| 内存使用 | 最小 | 预计算曲线数据 |
| 可预测性 | 运行时分支 | 完全确定 |

## 烘焙流程

### 入口

```cpp
FBakedAnimation FAnimationCompiler::BakeAllStages(
    UTextAnimationBlueprint* Blueprint,
    const FString& Text
);
```

### 第一阶段：字形分类

```cpp
TArray<FGlyphScheduleInfo> ScheduleInfos = BuildScheduleInfos(Text);
```

`BuildScheduleInfos` 将文本字符串分解为字形数组，每个字形带有分类标记：

| 标记 | 含义 | 示例 |
|------|------|------|
| bIsWhitespace | 空白字符 | 空格、制表符 |
| bIsPunctuation | 标点符号 | 句号、逗号、感叹号 |
| bIsCJK | 中日韩字符 | 你、日、한 |
| bIsDecorator | 装饰器字符 | `<` `>` 标签字符 |

### 第二阶段：构建图层

Beta 支持两种构建路径：

#### 路径 A：BlueprintNativeEvent（推荐）

1. 调用 `CDO->BuildDefaultAnimation(GlyphCount, Text)`
2. 蓝图中的自定义逻辑通过 `UGlyphAnimationLayer` 和 `UGlyphAnimationFactory` 构建动画
3. 返回 `FBakedStage`

#### 路径 B：资产回退

当 BlueprintNativeEvent 未被覆盖时，使用 `GlyphAnimations` 数组中的 `UGlyphAnimation` 资产：

1. 遍历 `GlyphAnimations[]` 为每阶段创建 Layer
2. Factory 合并所有 Layer
3. Factory->Bake()

### 第三阶段：三步烘焙

`UGlyphAnimationFactory::Bake()` 执行三步：

```
Bake()
  ├─ 步骤1: 每层独立烘焙
  │   └─ For each layer:
  │       ├─ 从 UGlyphAnimation 提取 21 通道曲线
  │       ├─ 按 BlendMode + Schedule 生成每字形曲线
  │       └─ 存储为 FPerLayerCurves（TArray<FRichCurveKey>*21）
  │
  ├─ 步骤2: 复制到 FBakedGlyph
  │   └─ 将每层的 FPerLayerCurves 复制到对应字形
  │       └─ FBakedGlyph::LayerCurves = TArray<FPerLayerCurves>
  │
  └─ 步骤3: Factory 后处理
      └─ 应用全局偏移、缩放、抖动等
      └─ 返回 FBakedStage
```

### 第四阶段：指纹生成

```cpp
uint64 TextFingerprint = CityHash64(Text);
uint64 BPFingerprint = CityHash64(
    BP->GeneratedClass + 
    BP->CompileCount + 
    TrackSignatures + 
    SectionSignatures
);
```

## 缓存机制

```cpp
bool UTextAnimInstance::NeedsRebake() const
{
    // 1. 检查指纹
    if (CurrentTextFingerprint != CachedTextFingerprint)
        return true;
    if (CurrentBPFingerprint != CachedBlueprintFingerprint)
        return true;
    
    // 2. 检查编译计数
    if (SourceBlueprint->CompileCount != CachedCompileCount)
        return true;
    
    // 3. 检查冷却帧数
    if (GFrameCounter - LastRebakeFrameCounter < MinFramesBetweenRebakes)
        return false;
    
    return false;
}
```

### 缓存失效场景

| 场景 | 触发条件 | 重新烘焙 |
|------|----------|----------|
| 文本更新 | SetText() 调用，指纹不匹配 | 是 |
| 蓝图变量更新 | SetBlueprintVariable() 调用 | 是 |
| 蓝图重编译 | CompileCount 增加 | 是 |
| 参数快速变化 | 同一参数在 3 帧内多次修改 | 否（冷却保护） |

## 曲线缓存

`FGlyphCurveSet` 内部也使用了缓存机制：

```cpp
UGlyphAnimation* Animation;
FGlyphCurveSet CachedExtractedCurves;
uint64 CachedExtractedFingerprint;

FGlyphCurveSet ExtractCurves(UGlyphAnimation* Animation)
{
    if (Animation->CachedExtractedFingerprint == CurrentFingerprint)
        return Animation->CachedExtractedCurves;  // 缓存命中
    
    // 提取并缓存...
}
```

## 性能特征

| 指标 | 典型值 | 说明 |
|------|--------|------|
| 烘焙时间 | 1-5ms / 100字符 | 编辑器编译时，非运行时 |
| 运行时评估 | <0.01ms / 字形 | 直接读取预计算数据 |
| 缓存命中率 | >95% | 大多数帧无烘焙 |
| 内存开销 | ~2KB / 字形 | 包含全部21通道曲线 |

## 最佳实践

| 建议 | 原因 |
|------|------|
| 避免频繁修改 Blueprint 变量 | 每次修改触发重新烘焙 |
| 使用 SeedJitter 替代随机 | 随机值导致缓存永不命中 |
| 预定义动画样式 | 避免运行时动态构建图层 |
| 合理设置冷却帧数 | 平衡响应性与性能 |
| 批量更新变量 | 减少重新烘焙次数 |

## 限制

- 烘焙是同步操作，大文本（>10000 字符）可能在编辑器中产生明显延迟
- 不支持烘焙时的异步/后台编译
- 指纹基于 CityHash64，极低概率的哈希碰撞可能被忽略
