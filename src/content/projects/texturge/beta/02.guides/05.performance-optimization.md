# 性能优化

本文介绍 Texturge Beta 的性能特征和优化策略，帮助你在各种硬件配置上获得最佳帧率。

## 性能概览

Texturge Beta 通过编译期烘焙管线实现了显著的性能提升。核心原则：**尽可能多地在编译期计算，最小化运行时开销。**

### 性能特征

| 指标 | Beta | Alpha（参考） | 提升 |
|------|------|-------------|------|
| 运行时每字形开销 | <0.01ms | ~0.05ms | ~5x |
| 100 字符文本每帧 | <1ms | ~5ms | ~5x |
| 烘焙缓存命中率 | >95% | N/A | — |
| 内存每字形 | ~2KB | ~0.5KB | 更大但可预测 |

## 烘焙管线优化

### 缓存命中

烘焙管线的核心优化是缓存系统。大多数帧不需要重新烘焙：

```
if (NeedsRebake())  → 只有指纹不匹配时才烘焙
{
    // 执行烘焙（1-5ms）
    BakeAnimation();
}
// 大多数帧直接使用缓存数据
```

### 优化建议

| 策略 | 效果 | 权衡 |
|------|------|------|
| 使用固定文本 | 永不重新烘焙 | 不支持动态文本 |
| 批量更新变量 | 减少烘焙次数 | 延迟响应 |
| 增大冷却帧数 | 避免参数抖动 | 延迟烘焙 |
| 预加载常用动画 | 第一次使用免烘焙 | 内存增加 |

## 字形分类与跳过

### 跳过无动画字形

通过 `FGlyphScheduleInfo::bSkipAnimation` 跳过空白字符和装饰器：

```cpp
FGlyphScheduleBuilder::SkipWhitespace(Schedule);
```

空白字符（空格、制表符）通常不需要动画，跳过它们可显著减少计算量。

### 静态字形

被标记为 `bIsStatic = true` 的字形使用 `DefaultState` 而非曲线求值：

```cpp
// 静态字形直接使用默认状态，跳过所有曲线求值
if (Glyph.bIsStatic)
    return Glyph.DefaultState;
```

## 普通文本 vs 多格式文本

| 对比 | AnimatedTextBlock | AnimatedRichTextBlock |
|------|-------------------|----------------------|
| 解析开销 | 无 | 每次 SetText 解析标签 |
| 求值开销 | 单动画求值 | 多动画并行求值 |
| 渲染开销 | 最低 | 略高（多 Run 渲染树） |
| 适用场景 | 简单打字效果 | 复杂混合动画 |

> [!IMPORTANT]
> 对于简单打字机效果，优先使用 `AnimatedTextBlock`；仅在需要多动画混合时使用 `AnimatedRichTextBlock`。

## 曲线求值优化

### FPerLayerCurves 高效求值

```cpp
// 高效：直接构建 FRichCurve 并求值
for (const FPerLayerCurves& Layer : Glyph.LayerCurves)
{
    // 21 通道独立求值（SIMD 友好的数据布局）
    float Opacity = BuildCurveFromKeys(Layer.OpacityKeys).Eval(Time);
    // ...
}
```

### 减少图层数量

每增加一个图层，运行时求值增加 21 通道的曲线计算。建议：

- 常规动画：1-3 层
- 复杂效果：最多 5 层
- 超过 5 层考虑预合并

## 控件优化

### bAutoPlay

手动控制播放比 `bAutoPlay = true` 更灵活且可预测：

```cpp
// 在适当时机手动播放，避免不必要的 Tick
AnimatedTextBlock->Play();
```

### 可见性管理

当控件不可见时（如 ScrollBox 外），停止 Tick：

```cpp
void OnVisibilityChanged(ESlateVisibility InVisibility)
{
    if (InVisibility == ESlateVisibility::Collapsed)
        Animator->Stop();
}
```

### 控件池

对于频繁创建/销毁的动画文本（如伤害数字、提示），使用对象池避免重复构造：

```cpp
// 从池中获取
UAnimatedTextBlock* Block = Pool->Get();
Block->SetText(NewText);
Block->Play();

// 用完返回池
Pool->Return(Block);
```

## CJK 文本优化

CJK 字符的逐字处理比其他文字系统更密集：

| 特性 | 拉丁文字 | CJK |
|------|----------|-----|
| 断词方式 | 按空格 | 逐字符 |
| 字形缓冲 | 较小 | 较大 |
| 调度复杂度 | 单词级 | 字符级 |

优化建议：
- 使用 `FCharBreakIterator` 预计算字符断点
- 对 CJK 文本使用 `bRequiresUniqueCurves` 确保逐字独立

## 音效优化

`UEventSoundComponent` 的 `MaxSoundsPerTick` 限制每帧播放音效数量：

```cpp
// 默认值 8，可根据性能调整
SoundComponent->MaxSoundsPerTick = 4;
```
