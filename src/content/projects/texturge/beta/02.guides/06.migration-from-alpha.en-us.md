# Migrating from Alpha to Beta

This guide helps existing Alpha users smoothly migrate to Texturge Beta.

## Major Changes Overview

| Change | Alpha | Beta |
|--------|-------|------|
| Animation definition | Track config only | Tracks + Layers + Factory |
| Animation compilation | Runtime interpolation | Compile-time bake |
| Multi-animation blend | Via RichText tags | Layer system + RichText |
| Custom animation logic | Not supported | BlueprintNativeEvent |
| Stage control | Manual | StageController automated |
| Sequencer track | FTextAnimationTrack | UMovieSceneGlyphAnimationTrack |

## Migration Steps

### 1. Plugin Update

1. Delete the old Texturge plugin (`Plugins/Texturge/`)
2. Install the Beta version plugin
3. Regenerate project files
4. Compile the project

> [!WARNING]
> Beta is not backward compatible with Alpha assets. Existing `UTextAnimationBlueprint` and `UTextAnimation` assets need to be recreated or manually migrated.

### 2. Asset Migration

#### Text Animation Blueprints

Alpha `UTextAnimationBlueprint` assets can still be opened, but:
- Old track configurations remain (backward-compatible reading)
- It is recommended to rebuild animations using the new Layer + Factory workflow
- The `GlyphAnimations` array replaces the old animation reference approach

#### UTextAnimation Assets

If you used `UTextAnimation` assets (Sequencer integration):
- Old `FTextAnimationTrack` is marked `@deprecated`
- New `UMovieSceneGlyphAnimationTrack` replaces it in Sequencer
- Track editor auto-registers with Sequencer

#### Rich Text

- Rich text tag system is largely unchanged
- `TextAnimationDataAsset` entry configuration is the same
- Consider moving complex multi-tag text to the Layer system

### 3. Blueprint Code Migration

#### Old API (Alpha)

```cpp
// Old playback control (some APIs removed)
TextAnimator->SetAnimationBlueprint(BP);
TextAnimator->SetPlaybackMode(EPlaybackMode::Duration);
TextAnimator->SetCPS(30.0f);
TextAnimator->StartAnimating();
```

#### New API (Beta)

```cpp
// New StageController playback control
StageController->Play();
StageController->SetPlayDirection(EStagePlayDirection::Forward);
StageController->SetLoop(true);

// Access baked animation via AnimInstance
UTextAnimInstance* Instance = BP->CreateAnimInstance();
FBakedStage Stage = Instance->BuildDefaultAnimation(GlyphCount, Text);

// Runtime variable updates
Instance->SetBlueprintVariable(FName("Speed"), 2.0f);
```

### 4. C++ Code Migration

#### New Required Headers

```cpp
// New required includes
#include "Animation/AnimationCompiler.h"
#include "Animation/BakedAnimation.h"
#include "Animation/GlyphAnimationState.h"
#include "Animation/GlyphAnimationLayer.h"
#include "Animation/GlyphAnimationFactory.h"
#include "Animation/GlyphScheduleInfo.h"
#include "Animation/TextAnimationStageController.h"
```

#### Applying Animation State

```cpp
// Beta new approach: get state from StageController
TArray<FGlyphAnimationState> GlyphStates;
StageController->EvaluateAllGlyphs(GlyphStates);

for (int32 i = 0; i < GlyphStates.Num(); ++i)
{
    const FGlyphAnimationState& State = GlyphStates[i];
    ApplyGlyphRenderState(State);
}
```

### 5. Sequencer Project Migration

If using Level Sequencer to control text animation:

- Old `TextAnimationTrack` is replaced by new `GlyphAnimationTrack`
- Recreate tracks and add keyframes in Sequencer
- Old track parameters (SelectionMode, FixedTotalDuration, etc.) are not needed in the new track

### 6. Editor Customization Migration

If you made custom extensions to the animation blueprint editor:
- `FTextAnimationBlueprintEditor` internal architecture is largely compatible
- New `FPreviewSourceMediator` manages preview sources
- Designer panel's SDesignSurface architecture is unchanged

## Function Mapping Table

| Alpha Function | Beta Equivalent |
|---------------|-----------------|
| `SetCPS(30)` | `StageController->Play()` + BP variable Duration |
| `SetPlaybackMode(Duration)` | StageController auto-manages time |
| `StartAnimating()` | `StageController->Play()` |
| `SkipToEnd()` | `StageController->RevealAll()` |
| Track `ApplicationMode` | `FGlyphScheduleInfo` schedule params |
| Manual stage management | `StageController` auto stage transitions |
| `OnCharacterRevealed` | `StageController->OnGlyphRevealed` |
| `SetTrackWeight()` | Layer BlendMode + micro-adjust params |

## FAQ

### Q: Will old assets crash when loaded directly?

No. Beta retains backward-compatible reading logic, but you should migrate to the new workflow soon to get all new features.

### Q: Will performance decrease?

On the contrary. Beta's compile-time bake pipeline far exceeds Alpha's runtime performance. The only increased resource consumption is slightly larger memory footprint (~2KB per glyph vs ~0.5KB).

### Q: Can I use Alpha and Beta in the same project?

No. Beta completely replaces the Alpha plugin. Back up your project before upgrading.

### Q: Is custom BlueprintNativeEvent required?

No. The default implementation uses assets from the `GlyphAnimations` array, similar to Alpha behavior. BlueprintNativeEvent is an optional advanced feature.
