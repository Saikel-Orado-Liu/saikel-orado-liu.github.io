# Bake Pipeline

The bake pipeline is Texturge Beta's most fundamental architectural change — moving animation computation from runtime to compile time, achieving zero-runtime-overhead animation evaluation.

## Concept

In the Alpha version, animation evaluation (track interpolation, per-character parameter calculation) occurred every frame at runtime. Beta introduces `FAnimationCompiler` — a pure function compiler that pre-compiles `UTextAnimationBlueprint` + text content into `FBakedAnimation` at editor time.

### Why Bake?

| Comparison | Runtime Eval (Alpha) | Compile-Time Bake (Beta) |
|------------|---------------------|--------------------------|
| Computation | Every frame tick | Editor compile time |
| Performance | Scales linearly with character count | Zero runtime overhead |
| Memory usage | Minimal | Pre-computed curve data |
| Predictability | Runtime branches | Fully deterministic |

## Bake Flow

### Entry Point

```cpp
FBakedAnimation FAnimationCompiler::BakeAllStages(
    UTextAnimationBlueprint* Blueprint,
    const FString& Text
);
```

### Stage 1: Glyph Classification

```cpp
TArray<FGlyphScheduleInfo> ScheduleInfos = BuildScheduleInfos(Text);
```

`BuildScheduleInfos` decomposes the text string into a glyph array, each with classification flags:

| Flag | Meaning | Example |
|------|---------|---------|
| bIsWhitespace | Whitespace | Spaces, tabs |
| bIsPunctuation | Punctuation | Periods, commas, exclamation marks |
| bIsCJK | CJK characters | 你, 日, 한 |
| bIsDecorator | Decorator characters | `<` `>` tag characters |

### Stage 2: Build Layers

Beta supports two build paths:

#### Path A: BlueprintNativeEvent (Recommended)

1. Call `CDO->BuildDefaultAnimation(GlyphCount, Text)`
2. Custom logic in Blueprint builds animation via `UGlyphAnimationLayer` and `UGlyphAnimationFactory`
3. Return `FBakedStage`

#### Path B: Asset Fallback

When BlueprintNativeEvent is not overridden, uses `UGlyphAnimation` assets from the `GlyphAnimations` array:

1. Iterate `GlyphAnimations[]` to create Layer for each stage
2. Factory merges all Layers
3. Factory->Bake()

### Stage 3: Three-Step Bake

`UGlyphAnimationFactory::Bake()` executes three steps:

```
Bake()
  ├─ Step 1: Per-layer independent bake
  │   └─ For each layer:
  │       ├─ Extract 21 channel curves from UGlyphAnimation
  │       ├─ Generate per-glyph curves by BlendMode + Schedule
  │       └─ Store as FPerLayerCurves (TArray<FRichCurveKey>*21)
  │
  ├─ Step 2: Copy to FBakedGlyph
  │   └─ Copy each layer's FPerLayerCurves to corresponding glyph
  │       └─ FBakedGlyph::LayerCurves = TArray<FPerLayerCurves>
  │
  └─ Step 3: Factory post-processing
      └─ Apply global offset, scale, jitter, etc.
      └─ Return FBakedStage
```

### Stage 4: Fingerprint Generation

```cpp
uint64 TextFingerprint = CityHash64(Text);
uint64 BPFingerprint = CityHash64(
    BP->GeneratedClass + 
    BP->CompileCount + 
    TrackSignatures + 
    SectionSignatures
);
```

## Caching Mechanism

```cpp
bool UTextAnimInstance::NeedsRebake() const
{
    // 1. Check fingerprints
    if (CurrentTextFingerprint != CachedTextFingerprint)
        return true;
    if (CurrentBPFingerprint != CachedBlueprintFingerprint)
        return true;
    
    // 2. Check compile count
    if (SourceBlueprint->CompileCount != CachedCompileCount)
        return true;
    
    // 3. Check cooldown frames
    if (GFrameCounter - LastRebakeFrameCounter < MinFramesBetweenRebakes)
        return false;
    
    return false;
}
```

### Cache Invalidation Scenarios

| Scenario | Trigger | Re-Bake |
|----------|---------|---------|
| Text update | SetText() call, fingerprint mismatch | Yes |
| BP variable update | SetBlueprintVariable() call | Yes |
| BP recompile | CompileCount incremented | Yes |
| Rapid param change | Same param modified within 3 frames | No (cooldown) |

## Curve Caching

`FGlyphCurveSet` also uses internal caching:

```cpp
UGlyphAnimation* Animation;
FGlyphCurveSet CachedExtractedCurves;
uint64 CachedExtractedFingerprint;

FGlyphCurveSet ExtractCurves(UGlyphAnimation* Animation)
{
    if (Animation->CachedExtractedFingerprint == CurrentFingerprint)
        return Animation->CachedExtractedCurves;  // Cache hit
    
    // Extract and cache...
}
```

## Performance Characteristics

| Metric | Typical Value | Notes |
|--------|---------------|-------|
| Bake time | 1-5ms / 100 chars | Editor compile time, not runtime |
| Runtime eval | <0.01ms / glyph | Direct pre-computed data read |
| Cache hit rate | >95% | Most frames have no baking |
| Memory overhead | ~2KB / glyph | Includes all 21 channel curves |

## Best Practices

| Recommendation | Reason |
|----------------|--------|
| Avoid frequent BP variable changes | Each change triggers re-bake |
| Use SeedJitter instead of random | Random values cause permanent cache misses |
| Pre-define animation styles | Avoid runtime dynamic layer construction |
| Set cooldown frames reasonably | Balance responsiveness and performance |
| Batch variable updates | Reduce re-bake frequency |

## Limitations

- Baking is synchronous; large texts (>10,000 chars) may cause noticeable editor delay
- No async/background compilation during baking
- Fingerprints based on CityHash64; extremely low probability hash collisions may be ignored
