# 从 Alpha 迁移到 Beta

本指南帮助现有 Alpha 用户平滑迁移到 Texturge Beta。

## 重大变更概览

| 变更 | Alpha | Beta |
|------|-------|------|
| 动画定义 | 仅为轨道配置 | 轨道 + Layer + Factory |
| 动画编译 | 运行时插值 | 编译期烘焙 |
| 多动画混合 | 通过 RichText 标签 | Layer 系统 + RichText |
| 自定义动画逻辑 | 不支持 | BlueprintNativeEvent |
| 阶段控制 | 手动 | StageController 自动化 |
| Sequencer 轨道 | FTextAnimationTrack | UMovieSceneGlyphAnimationTrack |

## 迁移步骤

### 1. 插件更新

1. 删除旧版 Texturge 插件（`Plugins/Texturge/`）
2. 安装 Beta 版本插件
3. 重新生成项目文件
4. 编译项目

> [!WARNING]
> Beta 版本不向后兼容 Alpha 资产。现有 `UTextAnimationBlueprint` 和 `UTextAnimation` 资产需要重新创建或手动迁移。

### 2. 资产迁移

#### 文本动画蓝图

Alpha 的 `UTextAnimationBlueprint` 资产可以继续打开，但：
- 旧的轨道配置仍然保留（向后兼容读取）
- 建议使用新的 Layer + Factory 工作流重建动画
- `GlyphAnimations` 数组替代了旧的动画引用方式

#### UTextAnimation 资产

如果你使用了 `UTextAnimation` 资产（Sequencer 集成）：
- 旧的 `FTextAnimationTrack` 标记为 `@deprecated`
- 新的 `UMovieSceneGlyphAnimationTrack` 在 Sequencer 中替代
- 轨道编辑器自动注册到 Sequencer

#### 多格式文本

- 多格式文本标签系统基本不变
- `TextAnimationDataAsset` 条目配置相同
- 建议将复杂的多标签文本改用 Layer 系统

### 3. Blueprint 代码迁移

#### 旧 API（Alpha）

```cpp
// 旧的播放控制（已移除部分 API）
TextAnimator->SetAnimationBlueprint(BP);
TextAnimator->SetPlaybackMode(EPlaybackMode::Duration);
TextAnimator->SetCPS(30.0f);
TextAnimator->StartAnimating();
```

#### 新 API（Beta）

```cpp
// 新的 StageController 播放控制
StageController->Play();
StageController->SetPlayDirection(EStagePlayDirection::Forward);
StageController->SetLoop(true);

// 通过 AnimInstance 访问烘焙动画
UTextAnimInstance* Instance = BP->CreateAnimInstance();
FBakedStage Stage = Instance->BuildDefaultAnimation(GlyphCount, Text);

// 运行时变量更新
Instance->SetBlueprintVariable(FName("Speed"), 2.0f);
```

### 4. C++ 代码迁移

#### 新增头文件引用

```cpp
// 新增必需引用
#include "Animation/AnimationCompiler.h"
#include "Animation/BakedAnimation.h"
#include "Animation/GlyphAnimationState.h"
#include "Animation/GlyphAnimationLayer.h"
#include "Animation/GlyphAnimationFactory.h"
#include "Animation/GlyphScheduleInfo.h"
#include "Animation/TextAnimationStageController.h"
```

#### 应用动画状态

```cpp
// Beta 新方式：从 StageController 获取状态
TArray<FGlyphAnimationState> GlyphStates;
StageController->EvaluateAllGlyphs(GlyphStates);

for (int32 i = 0; i < GlyphStates.Num(); ++i)
{
    const FGlyphAnimationState& State = GlyphStates[i];
    ApplyGlyphRenderState(State);
}
```

### 5. Sequencer 项目迁移

如果项目中使用 Level Sequencer 控制文本动画：

- 旧的 `TextAnimationTrack` 改为新的 `GlyphAnimationTrack`
- 重新在 Sequencer 中创建轨道并添加关键帧
- 旧的轨道参数（SelectionMode、FixedTotalDuration 等）在新轨道中不需要

### 6. 编辑器自定义迁移

如果你对动画蓝图编辑器做了自定义扩展：
- `FTextAnimationBlueprintEditor` 内部架构基本兼容
- 新的 `FPreviewSourceMediator` 管理预览源
- 设计器面板的 SDesignSurface 架构不变

## 功能对应表

| Alpha 功能 | Beta 对应 |
|-----------|----------|
| `SetCPS(30)` | `StageController->Play()` + BP 变量 Duration |
| `SetPlaybackMode(Duration)` | StageController 自动管理时间 |
| `StartAnimating()` | `StageController->Play()` |
| `SkipToEnd()` | `StageController->RevealAll()` |
| 轨道 `ApplicationMode` | `FGlyphScheduleInfo` 调度参数 |
| 手动管理阶段 | `StageController` 自动阶段转换 |
| `OnCharacterRevealed` | `StageController->OnGlyphRevealed` |
| `SetTrackWeight()` | Layer 的 BlendMode + 微调参数 |

## 常见问题

### Q: 旧资产直接加载会崩溃吗？

不会。Beta 保留了向后兼容的读取逻辑，但建议尽快迁移到新工作流以获得全部新功能。

### Q: 性能会下降吗？

相反。Beta 的编译期烘焙管线在运行时性能远超 Alpha。唯一增加的资源消耗是略大的内存占用（每字形 ~2KB vs ~0.5KB）。

### Q: 可以在同一个项目中使用 Alpha 和 Beta 吗？

不可以。Beta 完全替换 Alpha 插件。请备份项目后再升级。

### Q: 自定义 BlueprintNativeEvent 是否必须？

不必须。默认实现使用 `GlyphAnimations` 数组中的资产，与 Alpha 行为类似。BlueprintNativeEvent 是可选的高级功能。
