# Performance Optimization

This article covers Texturge Beta's performance characteristics and optimization strategies to help you achieve the best frame rates across hardware configurations.

## Performance Overview

Texturge Beta achieves significant performance gains through its compile-time bake pipeline. Core principle: **compute as much as possible at compile time, minimize runtime overhead.**

### Performance Characteristics

| Metric | Beta | Alpha (reference) | Improvement |
|--------|------|-------------------|-------------|
| Runtime per-glyph | <0.01ms | ~0.05ms | ~5x |
| 100-char text per frame | <1ms | ~5ms | ~5x |
| Bake cache hit rate | >95% | N/A | — |
| Memory per glyph | ~2KB | ~0.5KB | Larger but predictable |

## Bake Pipeline Optimization

### Cache Hits

The core optimization of the bake pipeline is the caching system. Most frames don't need re-baking:

```
if (NeedsRebake())  → Bake only when fingerprints mismatch
{
    // Execute bake (1-5ms)
    BakeAnimation();
}
// Most frames use cached data directly
```

### Optimization Tips

| Strategy | Effect | Trade-off |
|----------|--------|-----------|
| Use fixed text | Never re-bake | No dynamic text support |
| Batch variable updates | Reduce bake frequency | Delayed response |
| Increase cooldown frames | Avoid parameter jitter | Delayed baking |
| Preload common animations | No bake on first use | Increased memory |

## Glyph Classification & Skipping

### Skip Non-Animated Glyphs

Skip whitespace and decorators via `FGlyphScheduleInfo::bSkipAnimation`:

```cpp
FGlyphScheduleBuilder::SkipWhitespace(Schedule);
```

Whitespace characters (spaces, tabs) typically don't need animation; skipping them significantly reduces computation.

### Static Glyphs

Glyphs marked `bIsStatic = true` use `DefaultState` instead of curve evaluation:

```cpp
// Static glyphs use default state directly, skip all curve evaluation
if (Glyph.bIsStatic)
    return Glyph.DefaultState;
```

## Plain Text vs Rich Text

| Comparison | AnimatedTextBlock | AnimatedRichTextBlock |
|------------|-------------------|----------------------|
| Parse overhead | None | Parse tags each SetText |
| Eval overhead | Single animation eval | Multi-animation parallel eval |
| Render overhead | Lowest | Slightly higher (multi-run render tree) |
| Use case | Simple typewriter | Complex multi-animation blend |

> [!IMPORTANT]
> For simple typewriter effects, prefer `AnimatedTextBlock`; only use `AnimatedRichTextBlock` when multi-animation blending is needed.

## Curve Evaluation Optimization

### Efficient FPerLayerCurves Evaluation

```cpp
// Efficient: directly build FRichCurve and evaluate
for (const FPerLayerCurves& Layer : Glyph.LayerCurves)
{
    // 21-channel independent eval (SIMD-friendly data layout)
    float Opacity = BuildCurveFromKeys(Layer.OpacityKeys).Eval(Time);
    // ...
}
```

### Reduce Layer Count

Each additional layer adds 21 channels of curve computation at runtime. Recommendations:

- Regular animation: 1-3 layers
- Complex effects: max 5 layers
- Beyond 5 layers consider pre-merging

## Widget Optimization

### bAutoPlay

Manual playback control is more flexible and predictable than `bAutoPlay = true`:

```cpp
// Play manually at the right time, avoid unnecessary ticks
AnimatedTextBlock->Play();
```

### Visibility Management

When widgets are not visible (e.g., scrolled out of a ScrollBox), stop ticking:

```cpp
void OnVisibilityChanged(ESlateVisibility InVisibility)
{
    if (InVisibility == ESlateVisibility::Collapsed)
        Animator->Stop();
}
```

### Object Pooling

For frequently created/destroyed animated text (damage numbers, tips), use object pooling to avoid repeated construction:

```cpp
// Get from pool
UAnimatedTextBlock* Block = Pool->Get();
Block->SetText(NewText);
Block->Play();

// Return to pool when done
Pool->Return(Block);
```

## CJK Text Optimization

Per-character processing for CJK is more intensive than Latin scripts:

| Characteristic | Latin | CJK |
|---------------|-------|-----|
| Word breaking | By space | Per character |
| Glyph buffer | Smaller | Larger |
| Schedule complexity | Word level | Character level |

Optimization tips:
- Use `FCharBreakIterator` for pre-computed character break points
- Use `bRequiresUniqueCurves` for CJK text to ensure per-character independence

## Sound Optimization

`UEventSoundComponent`'s `MaxSoundsPerTick` limits sounds played per frame:

```cpp
// Default is 8, adjust based on performance
SoundComponent->MaxSoundsPerTick = 4;
```
