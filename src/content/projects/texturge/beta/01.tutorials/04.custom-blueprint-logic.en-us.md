# Custom Blueprint Animation Logic

This tutorial shows how to implement custom animation generation logic by overriding the `BuildDefaultAnimation` BlueprintNativeEvent — one of the most powerful new features of the Beta release.

## Overview

In the Alpha version, animation behavior was entirely determined by track configuration. Beta introduces `UTextAnimInstance::BuildDefaultAnimation` BlueprintNativeEvent, allowing you to dynamically generate animation data in Blueprint.

## Core Concepts

### BuildDefaultAnimation

```cpp
UFUNCTION(BlueprintNativeEvent, Category = "Texturge|Animation")
FBakedStage BuildDefaultAnimation(int32 GlyphCount, const FString& Text);
```

This function receives the glyph count and text content, returning an `FBakedStage` struct. The default implementation generates animation through `UGlyphAnimationFactory`, but you can completely override this behavior in Blueprint.

### Architectural Benefits

- **Compile-Time Execution**: Animation is baked at compile time, zero runtime overhead
- **Fingerprint Caching**: Re-bakes only when text or blueprint variables change
- **Full Data Access**: Access to text content, glyph scheduling info, and curve data

## Step 1: Create a Text Animation Blueprint

Create a `TextAnimationBlueprint` asset, name it `TABP_CustomWave`.

## Step 2: Add Blueprint Variables

Add variables in the blueprint's Class Defaults. Texturge Beta supports six Blueprint variable types:

| Variable Name | Type | Default | Description |
|---------------|------|---------|-------------|
| WaveAmplitude | float | 10.0 | Wave amplitude |
| WaveFrequency | float | 0.5 | Wave frequency |
| CharDuration | float | 0.1 | Per-character duration |
| TintColor | FLinearColor | (1,1,1,1) | Text color (optional) |
| StartDirection | FVector | (0,0,0) | Entry direction (optional) |
| bSkipSpaces | bool | true | Skip spaces (optional) |

> [!NOTE]
> Supported variable types: **float** / **int32** / **bool** / **FVector** / **FLinearColor** / **FVector2D**. All six types can be updated at runtime via `SetBlueprintVariable`.

## Step 3: Override BuildDefaultAnimation

1. Open the blueprint's Event Graph
2. Override `BuildDefaultAnimation` in the Functions list
3. Implement custom logic:

### Blueprint Logic Flow

```
Event BuildDefaultAnimation (GlyphCount, Text)
  → BuildScheduleInfos(Text) → ScheduleInfos array
  → Create UGlyphAnimationLayer (using an Opacity track animation)
  → Create UGlyphAnimationFactory
  → Set base layer
  → For each glyph Index:
     → Calculate sine wave offset: sin(Index * WaveFrequency) * WaveAmplitude
     → SetTranslationAt(Index, FVector2D(0, sine_value))
     → SetStartDelayAt(Index, Index * CharDuration)
  → AddLayer (translation offset layer)
  → Factory->Bake() → FBakedStage
  → Return baked stage
```

### Key Steps in Detail

#### 1. Build Schedule Infos

```cpp
TArray<FGlyphScheduleInfo> Schedule = BuildScheduleInfos(Text);
```

This static method generates `FGlyphScheduleInfo` for each character in the text, automatically classifying CJK characters, punctuation, whitespace, etc.

#### 2. Create Layers

```cpp
UGlyphAnimationLayer* BaseLayer = UGlyphAnimationLayer::CreateLayer(
    BaseAnimation,      // UGlyphAnimation asset (e.g., FadeIn)
    Additive,           // Blend mode
    Schedule            // Schedule array
);
```

#### 3. Custom Glyph Properties

Per-glyph adjustment methods on `UGlyphAnimationFactory`:

| Method | Effect |
|--------|--------|
| `SetStartDelayAt(Index, Delay)` | Set glyph start delay |
| `SetTranslationAt(Index, Offset)` | Translation offset |
| `SetScaleAt(Index, Scale)` | Scale adjustment |
| `SetRotationAt(Index, Degrees)` | Rotation angle |
| `SetOpacityAt(Index, Alpha)` | Opacity micro-adjustment |
| `SetColorAt(Index, Color)` | Color micro-adjustment |
| `SkipAt(Index, bSkip)` | Skip animation for glyph |
| `SetSeedJitterAt(Index, Jitter)` | Random jitter seed |

#### 4. Bake

```cpp
FBakedStage Result = Factory->Bake();
return Result;
```

`Bake()` performs three steps: per-layer independent bake → copy to `FPerLayerCurves` → factory post-processing.

## Example: Wave Effect

```
Function CustomWaveAnimation(Text, Amplitude, Frequency):
  Schedule = BuildScheduleInfos(Text)
  BaseLayer = CreateLayer(OpacityFadeIn, Additive, Schedule)
  Factory = CreateFactory(BaseLayer, Schedule)

  For each index i:
    Sine = Sin(i * Frequency) * Amplitude
    Factory.SetTranslationAt(i, (0, Sine))
    Factory.SetStartDelayAt(i, i * 0.08)

  Return Factory.Bake()
```

Effect: Each character appears sequentially (increasing delay) while floating in a sine wave pattern.

## Example: Random Entrance Effect

```
Function RandomEntrance(Text):
  Schedule = BuildScheduleInfos(Text)
  BaseLayer = CreateLayer(Opacity, Override, Schedule)
  Factory = CreateFactory(BaseLayer, Schedule)

  For each index i:
    RandAngle = Random(-30, 30)  // -30° ~ 30°
    RandX = Random(-100, 100)
    RandY = Random(-50, 50)
    RandDelay = Random(0, 0.5)
    Factory.SetRotationAt(i, RandAngle)
    Factory.SetTranslationAt(i, (RandX, RandY))
    Factory.SetStartDelayAt(i, RandDelay)

  Return Factory.Bake()
```

## Stage Control

The `FBakedStage` returned by `BuildDefaultAnimation` corresponds to the **Default** stage by default. To customize Intro and Outro stages:

1. Configure the `GlyphAnimations` array in `UTextAnimationBlueprint`
2. Specify `UGlyphAnimation` assets for Intro / Default / Outro stages separately
3. `FAnimationCompiler::BakeAllStages` automatically handles three-stage baking

## Best Practices

| Recommendation | Reason |
|----------------|--------|
| Call `BuildScheduleInfos` each time | Ensure schedule info is in sync with current text |
| Use `CreateFactoryFromText` | Simplifies text-to-factory conversion |
| Avoid using random in bake | Fingerprint cache reuses results; use `SeedJitter` instead |
| Keep bake functions pure | Ensure same input always returns same output |
| Pre-compute, don't runtime-compute | All custom logic executes at compile time |

## Runtime Parameter Updates

Although baking occurs at compile time, variables can be dynamically updated via `SetBlueprintVariable`:

```cpp
// Update wave amplitude at runtime
AnimInstance->SetBlueprintVariable(FName("WaveAmplitude"), 20.0f);
```

Variable updates trigger a re-bake (protected by a 3-frame cooldown).
