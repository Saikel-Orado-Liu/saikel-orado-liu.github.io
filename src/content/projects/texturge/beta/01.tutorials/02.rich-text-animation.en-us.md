# Rich Text Animation

This tutorial demonstrates how to blend multiple animation effects in a single text block using rich text tags.

## Concept Overview

Texturge's `AnimatedRichTextBlock` supports embedding custom tags within text to apply different text animation blueprints to different paragraphs, words, or even characters. This is extremely useful for dialog systems, tutorial prompts, and dynamic UI.

## Step 1: Create Animation Blueprints

First, create two text animation blueprints:

### TABP_Typewriter (Typewriter Effect)

| Setting | Value |
|---------|-------|
| Track | Opacity |
| Application Mode | PerCharacter |
| Invert Opacity | true |
| Keyframe 1 | (0.0, 0.0) |
| Keyframe 2 | (0.3, 1.0) |

### TABP_BounceIn (Bounce In Effect)

| Setting | Value |
|---------|-------|
| Track 1 | Opacity — Inverted, keyframes (0.0,0.0)→(0.3,1.0) |
| Track 2 | Translation — PerCharacter |
| Translation Keyframes | (0.0, (0,50))→(0.3, (0,0)) |
| Track 3 | Scale — PerCharacter |
| Scale Keyframes | (0.0, (0.5,0.5))→(0.15, (1.3,1.3))→(0.3, (1,1)) |

## Step 2: Create an Animation Data Asset

In the Content Browser, right-click and select **Miscellaneous → Data Asset**, choosing `TextAnimationDataAsset` as the class.

<figure class="img-placeholder"><figcaption>dataasset-config.avif — Data Asset configuration interface</figcaption></figure>

Add two entries in the Details panel:

| Tag Name | Type |
|----------|------|
| `typewriter` | `TABP_Typewriter` |
| `bounce` | `TABP_BounceIn` |

## Step 3: Set Up the Rich Text Widget

1. Add an **Animated Rich Text Block** to your UMG Widget
2. Set **Animation Data** → Select the DataAsset you just created
3. Set **bAutoPlay** → `true`

## Step 4: Write Tagged Text

In the **Text** property, use custom tags to mark different sections:

```xml
<typewriter>Hello, </><bounce>World!</>
```

This causes "Hello, " to reveal character by character with a typewriter effect, and "World!" to appear with a bounce-in effect.

## Tag Syntax Details

Texturge supports a rich tag syntax:

### Open/Close Tags

```xml
<typewriter>This text uses typewriter animation</>
```

### Using the id Attribute

```xml
<anim id="typewriter">Specify animation via id</>
```

### Mixing Standard Style Tags

```xml
<typewriter><Large>Large typewriter effect</></>
```

Standard UMG rich text styles (`<Large>`, `<Bold>`, etc.) still work normally and can be nested with animation tags.

### Multiple Animation Regions

```xml
<typewriter>Hello, </><bounce>Welcome to</><typewriter>Texturge!</>
```

Each `<>...</>` block runs its own animation independently.

## Parameter Overrides

In the DataAsset entry's `Parameter Overrides` map, you can override animation blueprint variables for specific tags:

| Parameter | Value | Effect |
|-----------|-------|--------|
| Duration | 0.5 | Speed up typing |
| CPS | 30.0 | 30 characters per second |

## Playback Mode

The `bSequentialPlayback` property of `AnimatedRichTextBlock` controls playback behavior between blocks:

| Mode | Behavior |
|------|----------|
| Parallel (false) | All animation blocks play simultaneously |
| Sequential (true) | Blocks play in tag appearance order |

Sequential playback is ideal for dialog systems, ensuring multiple speakers' text appears in order.

## Processing Pipeline

The rich text animation evaluation flow:

1. `FTagParser` parses tagged text into an `FTagNode` tree
2. `FRenderTreeBuilder` builds a render tree and matches animations by EntryIndex
3. `UTextAnimator` manages parallel/sequential playback logic
4. Each `FTextRun::OnPaint()` queries the corresponding `FAnimationFrameData` based on its block
5. The Slate renderer applies animation state per-glyph

## Debugging Tips

| Issue | Check |
|-------|-------|
| Tags not working | Confirm tag name matches DataAsset exactly (case-sensitive) |
| Animation not playing | Check bAutoPlay or confirm Play() was called |
| Style tags not working | Confirm StyleSet is properly set |
| Performance issues | Reduce parallel block count, use sequential playback |
