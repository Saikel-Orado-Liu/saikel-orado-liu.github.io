# Installation

CLIF Localization Suite is a localization plugin for Unreal Engine 5.8 with two modules: `ClifLocalizationSuite` (Runtime — CLIF data model and parser) and `ClifLocalizationSuiteEditor` (Editor — official pipeline integration, import/export and AI translation). This page covers installation, enabling and verification.

## Requirements

| Item | Requirement |
|:---|:---|
| Engine version | Unreal Engine 5.8 (`EngineAssociation: 5.8`) |
| Platforms | Win64 / Mac / Linux (`PlatformAllowList`) |
| Localization target | At least one Localization Target in the project (created in the Localization Dashboard) |
| Python | **Not required.** The plugin is pure C++ at runtime |
| Network (optional) | Only for AI translation, which calls the DeepSeek API |

> [!NOTE]
> The Runtime module has no editor dependencies, so Game and Shipping targets package normally. Import, export and AI translation all live in the Editor module and never ship in a runtime build.

## Install the plugin

### From Fab

1. Search for "CLIF Localization Suite" on Fab, or open the [product page](https://www.fab.com/listings/b53f5be1-1fd8-4ffb-ba33-2a1a3fa2cc5a)
2. Add the plugin to your Epic Games account library
3. Install it for the target engine version through the Epic Games Launcher

### From source

1. Copy the `ClifLocalizationSuite` folder into your project's `Plugins/` directory (create it if needed)
2. Open the project and choose **Yes** when Unreal offers to rebuild the new plugin

    <figure class="img-placeholder"><figcaption>images/plugin-compile-prompt.png — UE5 检测到新插件后弹出“是否重新编译”提示，选择“是” — The "rebuild modules?" prompt shown when Unreal detects a new plugin; choose Yes</figcaption></figure>

3. When the build finishes, open **Edit > Plugins** and search for "CLIF Localization Suite"
4. Enable the plugin and restart the editor

> [!IMPORTANT]
> The distribution is **source-only**: `.uplugin` plus `Source/` and `Content/`, with no `Binaries/`, `Intermediate/` or `.pdb` files. The first enable therefore compiles locally, which needs a working C++ toolchain.

## Enable the plugin

1. Open **Edit > Plugins**
2. Search for "CLIF Localization Suite"

    <figure class="img-placeholder"><figcaption>images/plugin-manager-checkbox.png — 插件管理器中搜索 “CLIF Localization Suite”，勾选插件行 — The Plugin Manager filtered to "CLIF Localization Suite" with the plugin enabled</figcaption></figure>

3. Tick the **CLIF Localization Suite** checkbox
4. Click **Restart Now** in the bottom-right corner

> [!NOTE]
> On startup the plugin registers itself as an official `LocalizationService` modular feature **and selects itself as the active provider**, so the Localization Dashboard already has the CLIF buttons on its toolbar. The log prints `provider registered and selected as modular feature 'LocalizationService'`.

## Choose the provider

If the CLIF buttons are missing from the Dashboard toolbar:

1. Open **Tools > Localization Dashboard**
2. Pick **CLIF Localization Suite** in the **Localization Service Provider** dropdown
3. Reopen the Dashboard — the Target and TargetSet toolbars now show **CLIF 导入 / CLIF 导出 / AI 翻译** on the right-hand side

> [!TIP]
> The provider choice is snapshotted when the Dashboard builds its toolbars. If the Dashboard was already open, close and reopen it.

## Show plugin content

The plugin ships its own localization data (7 targets × 15 languages). To browse it:

1. Open the **Settings** menu in the top-left of the Content Browser
2. Tick **Show Plugin Content**
3. The targets' manifests, archives and compiled resources appear under `Plugins/ClifLocalizationSuite/Content/Localization/`

## Project settings

Open **Edit > Project Settings > Plugins > CLIF Localization Suite** — four categories:

| Category | Contents |
|:---|:---|
| **Identity** | `CLIF Namespace`: the project identifier used in CLIF headers (lowercase kebab-case) |
| **Semantic Mapping** | The `Clan to Namespace`, `Namespace to Type` and `Namespace to Emotion` tables |
| **Workflow** | Default directories for the import and export file dialogs |
| **AI Translation** | DeepSeek API key, model, prompts, batching and retry parameters |

Every field is documented in the [settings reference](../../../reference/settings/settings).

## C++ module dependencies

To reference CLIF types from your game or plugin `Build.cs`:

```csharp
// Runtime: CLIF data model, parser, validator, serializer, semantic mapping and settings
PublicDependencyModuleNames.AddRange(new string[]
{
    "Core", "CoreUObject", "Engine", "DeveloperSettings",
    "ClifLocalizationSuite"
});
```

```csharp
// Editor: importer, exporter, AI translation and the GatherText commandlets
PrivateDependencyModuleNames.AddRange(new string[]
{
    "ClifLocalizationSuiteEditor"
});
```

> [!NOTE]
> The runtime module is named `"ClifLocalizationSuite"`. `ClifLocalizationSuiteEditor` is `Type: Editor`, so it only builds for editor targets and is never part of a Game or Server target.

## Verify the installation

### 1. Console self-check

Run this in the editor console (`~`):

```text
ClifLocalizationSuite.Hello
```

The log line `ClifLocalizationSuite.Hello: parser, importer and exporter are active (M5 integration).` confirms the modules loaded.

### 2. Dashboard buttons

Open **Tools > Localization Dashboard**, select a target and confirm the toolbar shows **CLIF 导入 / CLIF 导出 / AI 翻译**.

### 3. Round-trip smoke test

1. **CLIF 导出** → pick an output directory → confirm each culture directory contains a `.clif` file and the root holds the `.clifmap.json`
2. **CLIF 导入** → pick one of those `.clif` files → confirm the official progress window completes and the log can be copied
3. Open **Window > Localization > Translation Editor** and confirm the entries and translations look right

The full walkthrough is in [Dashboard workflow](../dashboard-workflow).

> [!TIP]
> If the build fails, check that the engine is UE 5.8, that the project has generated C++ project files, and that the module names are spelled `ClifLocalizationSuite` / `ClifLocalizationSuiteEditor`.
