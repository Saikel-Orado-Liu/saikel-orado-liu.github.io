# Vocabularies and Mapping

CLIF's fixed tag sets are **closed**: any value not listed here is a validation error. This page gives the complete vocabularies, the meaning of each value and the plugin's derivation rules.

## type (26)

### Word level (11)

| Value | Meaning |
|:---|:---|
| `noun` | Noun: a thing, place or concept |
| `verb` | Verb: an action or state |
| `adjective` | Adjective: a property or quality |
| `adverb` | Adverb: manner, time or degree |
| `pronoun` | Pronoun |
| `numeral` | Numeral |
| `preposition` | Preposition / postposition |
| `conjunction` | Conjunction |
| `particle` | Grammatical particle |
| `interjection` | Interjection / exclamation |
| `proper-noun` | Proper noun: person, place, brand, ship or block name |

### Phrase level (6)

| Value | Meaning |
|:---|:---|
| `noun-phrase` | Multi-word noun phrase |
| `verb-phrase` | Multi-word verb phrase |
| `adjective-phrase` | Multi-word adjective phrase |
| `adverb-phrase` | Multi-word adverb phrase |
| `fixed-phrase` | Fixed compound / fixed multi-word term (e.g. "The Block of Grass") |
| `idiom` | Idiom, fixed expression |

### Text / function level (9)

| Value | Meaning |
|:---|:---|
| `sentence` | A standalone sentence with no special function |
| `description` | Descriptive text: items, abilities, quests, products |
| `narration` | Story / voice-over narration |
| `dialogue` | Spoken dialogue |
| `monologue` | Inner thoughts / monologue |
| `prompt` | UI guidance, tooltips, hint text |
| `label` | Short UI label, button, menu item |
| `subtitle` | Dialogue subtitle |
| `accessibility-cue` | Accessibility-oriented subtitle cues (e.g. the hard-of-hearing sound cue `[door creaks]`) |

> [!NOTE]
> Entries in a `glossary` variant **should** use the term-level subset (11 word level + 6 phrase level = 17 values); using any other `type` is warned about by the strict validator but is not treated as an error.

## emotion (23)

| Value | Meaning |
|:---|:---|
| `neutral` | No marked emotion; ordinary expression |
| `objective` | Objective statement, informational (narration, labels, nouns); **the default for non-speech** |
| `mechanical` | Deliberately emotionless machine / robot tone; **never a default** |
| `joyful` | Happy, positive, celebratory |
| `sad` | Sorrow, regret, disappointment |
| `angry` | From irritation to rage |
| `fearful` | Fear, dread, panic |
| `surprised` | Unexpected discovery, shock |
| `curious` | Interest, inquiry, wanting to know |
| `disgusted` | Disgust, revulsion |
| `anxious` | Worry, unease |
| `calm` | Reassuring, soothing, composed |
| `playful` | Teasing, humorous, light |
| `serious` | Solemn, grave, formally important |
| `urgent` | Time pressure, warning |
| `romantic` | Affection, intimacy, flirtation |
| `hopeful` | Optimism, encouragement |
| `grateful` | Thanks, gratitude |
| `formal` | High register, respect, ceremony |
| `informal` | Casual, familiar |
| `polite` | Courteous, gentle request |
| `rude` | Blunt, insulting, aggressive |
| `nostalgic` | Nostalgia, wistfulness |

- **The value is always a list** (at least one element): `emotion: [calm, polite]`
- Multiple tags are **conjunctive**: `[anxious, polite]` = anxious and polite
- Contradictory combinations (e.g. `[formal, informal]`) are legal but should be avoided; the validator can emit a warning

### Default-value rules

When `emotion` is not written explicitly it is derived from the effective `type`:

| Effective type | Default emotion |
|:---|:---|
| `dialogue`, `monologue`, `idiom` | `[neutral]` |
| Everything else | `[objective]` |

An explicitly written `emotion` always overrides the default.

## status (4)

| Value | Meaning | Is `target` mandatory |
|:---|:---|:---|
| `initial` | No target text yet (extracted state) | May be omitted |
| `translated` | Target text exists, not yet human reviewed | **Mandatory** |
| `reviewed` | Passed (human) review | **Mandatory** |
| `final` | Locked and ready for release | **Mandatory** |

State machine: `initial → translated → reviewed → final`, and any state can go back to `translated` (a source change / rework invalidates the review). It is **mandatory on every entry, with no default**.

> [!NOTE]
> `status: initial` carrying a `target` is a **legal but warned-about** combination (the validator reports `target is present but status is 'initial'`). On import the plugin treats it as `initial`: it writes the manifest only and no archive translation.

## variant (2)

| Value | Meaning |
|:---|:---|
| `standard` (default) | An ordinary translation unit file |
| `glossary` | A glossary file: every entry is a term rather than a passage of prose, with exactly the same syntax and fields |

`glossary` conventions: `clan` is recommended to be the served clan plus a `-terms` suffix (`settings` → `settings-terms`), and a project-wide shared glossary uses `clan: terms`; it is referenced by standard files through `dependency`; entries whose `status` is `reviewed` / `final` **must not be overwritten**.

## How the plugin derives these fields

### Import (CLIF → UE)

| CLIF | Landing place |
|:---|:---|
| `type` | `clif.type` in the archive `KeyMetadataObj` (the entry wins, otherwise the group's inherited value) |
| `emotion` | `clif.emotion` (comma-joined) |
| `status` | `clif.status`; `initial` writes the manifest only |
| `context` | `clif.context` + the manifest's `SourceLocation` |

### Export (UE → CLIF)

| CLIF | Priority |
|:---|:---|
| `type` | `clif.type` → `Namespace to Type` → `sentence` + warning |
| `emotion` | `clif.emotion` → `Namespace to Emotion` → the default rule for the `type` |
| `status` | `clif.status` (∈ vocabulary and not `initial`) → `translated` when a translation exists, `initial` when it does not |
| `context` | `clif.context` → `SourceLocation` |

### Default mapping table

```text
clan ⇄ UE Namespace         type 映射                    emotion 映射
category        ⇄ UObjectCategory          → label          —
tooltip         ⇄ UObjectToolTips          → prompt         —
short-tooltip   ⇄ UObjectShortTooltips     → prompt         —
display-name    ⇄ UObjectDisplayNames      → proper-noun    —
proper-noun     ⇄ UObjectDisplayNames      → proper-noun    —
dialogue        ⇄ Dialogue                 → dialogue       → neutral
```

The full explanation is in [semantic mapping](../../../guides/semantic-mapping/mapping).

## Common mistakes

| Wrong | Right | Reason |
|:---|:---|:---|
| `emotion: calm` | `emotion: [calm]` | List fields must carry square brackets |
| `emotion: "calm"` | `emotion: [calm]` | Tags take no quotes, and must be a list |
| `type: "label"` | `type: label` | Tags take no quotes |
| `status: "final"` | `status: final` | Same as above |
| `reference: "src/ui.cpp:12"` | `reference: ["src/ui.cpp:12"]` | A list field, so even a single item needs square brackets |
| `dependency: "terms.clif"` | `dependency: ["terms.clif"]` | Same as above |
| `type: paragraph` | Choose `description` / `sentence` by meaning | `paragraph` is not one of the 26 vocabulary values |
| `emotion: Sadness` | `emotion: [sad]` | The vocabulary only accepts lowercase exact values |
| `status: Final` | `status: final` | Same as above |
